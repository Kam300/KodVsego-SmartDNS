# Код Всего · Smart DNS

Локальная доработка [hb-ai-xbox-dns](https://github.com/neiroseti-ai/hb-ai-xbox-dns/). Переключение DNS с сохранением исходных настроек, светлой/тёмной темой и ссылкой на [Код Всего](https://t.me/TotalC0de).

[Скачать программу для Windows](https://github.com/Kam300/KodVsego-SmartDNS/releases/latest) · [Сообщить об ошибке](https://github.com/Kam300/KodVsego-SmartDNS/issues) · [Разработчик в Telegram](https://t.me/TotalCodeAdmin)

Распаковывать и устанавливать не требуется: скачайте EXE из раздела Releases и запустите. Для изменения DNS потребуется подтвердить запрос Windows.

Известное ограничение DNS-AI: DNS-ответ для Gemini может приходить, хотя соединение с указанным узлом недоступно. Успешный тест DNS не подтверждает работу Gemini или устранение ошибки региона. В этом случае попробуйте другого провайдера.

## Текущая сборка

В 2.19.2 тест DNS-AI явно проверяет сайт Gemini (gemini.google.com) и его API (generativelanguage.googleapis.com) через DoH. Результат каждого запроса виден в отчёте теста; это проверка DNS, а не авторизованного доступа к Gemini.

В 2.19.1 добавлен DNS-AI: 194.87.196.13 / 186.246.49.127, только DoH https://dns.dns-ai.ru/dns-query. Проверка использует WinHTTP с HTTP/2, поскольку прежний HTTP/1.1 получал ответ 505. Обычный DNS для DNS-AI запрещён. Поддерживается встроенный DoH Windows 11; локальная служба для Windows 10 не устанавливается. Успешный DNS-ответ не гарантирует доступ к API Antigravity.

Номер версии расположен между «Код Всего» и ссылкой канала. Технические ошибки предлагают сохранить диагностический TXT и вручную отправить его https://t.me/TotalCodeAdmin. Отмена UAC, отсутствие сети, VPN, недоступность DNS и ожидание закрытия браузера не предлагают отчёт. Отчёт собирается только при сохранении; аккаунты, история и содержимое файлов не читаются, известные ключи и путь профиля скрываются. Автоматической отправки нет.

В версии 2.7.1 диалоги можно перемещать: удерживайте левую кнопку мыши на заголовке или свободной верхней части окна и перетаскивайте. Кнопки и прокрутка текста сохраняют обычное поведение.

`KodVsego_SmartDNS.2.19.2.exe`, версия 2.19.2. Требуется Windows 10 версии 2004 (сборка 19041) или новее, либо Windows 11, и .NET Framework 4.8. Окно открывается с обычными правами. При включении, выключении или смене DNS Windows запрашивает повышение прав для короткоживущего процесса того же EXE. Отмена UAC не меняет DNS. Тема и ссылки работают без повышения прав.

Ранние файлы `HB_AI_Xbox_DNS*.exe`, `KodVsego_SmartDNS.themes.exe`, `KodVsego_SmartDNS.light.exe`, `KodVsego_SmartDNS.native.exe` и ссылки на исходный GitHub Releases относятся к предыдущим сборкам. Актуальная локальная сборка создаётся командой `build.bat`.

## Как работает

- DNS меняется напрямую через `SetInterfaceDnsSettings` из системной `iphlpapi.dll`. Программа не запускает PowerShell, не передаёт команды в Base64 и не содержит встроенных скриптов. Кэш очищается через `DnsFlushResolverCache`.
- До первого изменения для каждого адаптера сохраняются GUID, ручной/автоматический режим и списки IPv4/IPv6 DNS. Резервная копия хранится в `HKLM\SOFTWARE\HbAi\SmartDns`, значение `Backup`, и совместима с предыдущей локальной сборкой.
- При переключении сервиса исходная копия не перезаписывается. Выключение восстанавливает только сохранённые адаптеры. Недоступные адаптеры остаются в копии для повторного восстановления.
- При ошибке программа пытается вернуть исходные настройки. Если откат не завершён, копия сохраняется и показывается ошибка.
- Для провайдеров без IPv6 адресов включение оставляет прежние настройки IPv6.
- Тема переключается значком луны/солнца вверху справа. Выбор хранится в `HKCU\SOFTWARE\KodVsego\SmartDns`, значение `Theme`.
- Интерфейс масштабирует текст, геометрию и области нажатия вместе и ограничивает размеры окна рабочей областью экрана.

Настройки, утраченные исходной версией до создания копии, автоматически восстановить невозможно. Если адреса сервиса уже заданы, а копии нет, окно показывает «Найден DNS сервиса». При выключении предлагается с явным подтверждением перейти на автоматический DNS только для активных адаптеров и семейств, где все ручные DNS входят в список программы (включая старые адреса Xbox). Смешанные и сторонние адреса не меняются. Перед операцией создаётся копия текущих настроек для отката при сбое. Если копия уже появилась, приоритет имеет обычное восстановление. Общего сброса всех адаптеров нет.

## Сборка

Запустите `build.bat`. Используется системный компилятор .NET Framework, дополнительные пакеты не скачиваются. Результат — `KodVsego_SmartDNS.2.19.2.exe`.

Основные файлы:

- `XboxDns.cs` — интерфейс, темы и список провайдеров.
- `NativeDns.cs` — Windows API, резервная копия, восстановление и валидация.
- `ProcessSecurity.cs` — ограничение обычного поиска нативных DLL каталогом System32 и системная рабочая папка; применяется в начале Main к интерфейсу и служебному процессу. Это не ограничивает явно заданные абсолютные пути, уже загруженные модули и переопределения со стороны загрузчика Windows.
- `tests/ProcessSecurity.Tests.cs` — 3 проверки реального загрузчика на безвредных текстовых файлах-заглушках: системная рабочая папка, исключение папки EXE/рабочей папки/PATH из стандартного поиска и успешная загрузка системной библиотеки.
- `DnsElevation.cs` — запрос UAC только для изменения DNS и передача результата через локальный канал с ограниченными правами и проверкой процессов. Произвольные скрипты и адреса через этот канал не принимаются.
- `AssemblyInfo.cs` — название и версия сборки.
- `tests/DnsElevation.Tests.cs` — 13 проверок аргументов, защищённого канала, передачи ошибок и режима запуска. Запрос UAC и реальное изменение DNS в них не выполняются.
- `tests/NativeDns.Tests.cs` — 25 проверок с имитацией операций записи и отдельной проверкой чтения Windows API. Реальные DNS и резервные копии тесты не меняют.
- `preview.ps1` — вспомогательный инструмент разработки: загружает форму и рисует холст, не переключая DNS. В приложение не встраивается.

Пример запуска проверок из PowerShell в этой папке:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run.ps1 -LiveHttps
```

## Подсказка после смены DNS и проверка VPN — версия 2.7.3

В окне есть подсказка полностью перезапустить браузер или приложение с сервисом после смены DNS. Сам переключатель DNS перезапускать не требуется. После успешного включения/смены сервиса показывается напоминание.

VPN проверяется при нажатии включения DNS и при смене провайдера, если DNS включён: проверяются активные сетевые адаптеры, тип PPP/Tunnel и названия распространённых VPN. Отдельная кнопка и периодический опрос удалены. При признаках VPN или ошибке проверки появляется предупреждение с возможностью отказаться до UAC и изменения DNS. Выключение DNS остаётся доступным для восстановления настроек и не требует проверки VPN.

Проверка приблизительная: не гарантирует обнаружение VPN в браузере, на роутере или нестандартного клиента; некоторые PPP/туннельные адаптеры могут не быть VPN. Отсутствие признаков обозначается именно так, а не утверждением «VPN выключен». VPN, прокси и настройки защиты автоматически не изменяются.

Логика — VpnCheck.cs, 14 проверок — tests/VpnCheck.Tests.cs. Для проверки внешнего вида используется preview.ps1; отрисовка окна не запускает проверку VPN и не меняет DNS.

## Диалоги — версия 2.7.3

Сообщения после смены DNS, ошибки DNS и подтверждения VPN/автоматического DNS используют StyledDialog.cs: текущую тему приложения, шрифты, скругления и бирюзовые кнопки. Подтверждения открываются с действием «Отмена» по умолчанию; Escape и крестик не подтверждают операцию. Длинные сообщения прокручиваются, высота ограничена рабочей областью экрана. Системный запрос UAC и сообщение о сбое безопасного запуска до загрузки интерфейса остаются стандартными окнами Windows.

В 2.6.2 крестик диалога и основного окна рисуется общим методом: две линии без подложки. После ограничения высоты окна Windows положение кнопок, высота текста и скруглённая область пересчитываются по фактическому размеру окна; снизу сохраняется отступ.

В 2.6.3 у напоминания «После смены DNS» есть отдельная кнопка «Больше не показывать»: она закрывает окно и сохраняет `HideDnsReminder=1` (DWORD) в `HKCU\SOFTWARE\KodVsego\SmartDns`. «Понятно», крестик и Escape закрывают только текущее сообщение. Ошибки DNS, предупреждения VPN и подтверждения восстановления не скрываются. Чтобы вернуть напоминание, удалите значение `HideDnsReminder` или задайте ему 0 и перезапустите приложение.

Предпросмотр: `preview.ps1 -Theme Dark -Dialog Success`, варианты `Warning` и `LongError`. Режим диалогов ненадолго показывает только тестовое окно, не меняет DNS и не запускает проверку VPN.

## Дополнительный DNS Antigravity — версия 2.7.3

Галочка «Доп. DNS Antigravity» включает отдельные точные правила NRPT для `cloudcode-pa.googleapis.com` и `daily-cloudcode-pa.googleapis.com`, с DNS GeoHide `159.194.200.33` и `193.233.112.67`. Настройка независима от основного переключателя и выбранного провайдера. По умолчанию выключена; включение требует подтверждения и прав администратора. После перезапуска галочка отражает реально установленные нами правила Windows. Правила сохраняются при закрытии программы; снимите галочку для отключения. Основная кнопка выключения DNS их не удаляет.

Используется системный DNS CIM-провайдер Windows через `System.Management`, без запуска PowerShell. Правила имеют собственные Comment/DisplayName. В обычном режиме удаляются только наши правила для этих двух доменов; чужие правила не заменяются и не удаляются. Исключение — отдельная подтверждённая принудительная замена, описанная ниже. При конфликте с другим анлокером, VPN или действующей политикой организации включение останавливается. При сбое установки отменяются только новые правила; неполное состояние видно в интерфейсе, можно повторить отключение. После создания проверяются как локальные правила, так и действующая политика Windows; очищается DNS-кэш.

Список двух доменов проверен по [описанию confeden/Antigravity](https://github.com/confeden/Antigravity) (изучен commit `eac61a418498e3220d43e55b1b077617d3265691`). Это самостоятельная реализация DNS-настройки в нашем проекте; код, службы и ресурсы анлокера не включены. Полный анлокер также меняет клиент и использует прокси/службу. Одна настройка DNS не гарантирует устранения региональных или аккаунтных ограничений Antigravity. Файл hosts, файлы Antigravity, сертификаты, IPv6-приоритет и автозапуск эта опция не меняет. Сторонний DNS получает запросы этих двух доменов.

Реализация — `AntigravityDns.cs`; 21 проверка в `tests/AntigravityDns.Tests.cs` покрывает имитацию включения, удаления, конфликтов и отката, чтение реального CIM-провайдера и обработку ответов Windows. Проверки не изменяют реальные DNS/NRPT. Предпросмотр `preview.ps1` поддерживает `-AgPreview Off|On|Partial|External|Unknown`.

## Принудительная замена DNS Antigravity — версия 2.7.3

Если опцию блокируют существующие правила другого анлокера, диалог предлагает «Применить принудительно» с действием «Отмена» по умолчанию. Режим разрешает заменить только списки DNS-серверов в точных правилах для двух доменов, помеченных `AG_UNLOCKER_NRPT_V2` или `AG_UNLOCKER_NRPT`. Имена, идентификаторы и остальные параметры этих правил сохраняются. Общие правила, правила с дополнительными доменами, дубликаты и неизвестные правила не заменяются; политики организации не редактируются.

До первого изменения прежние DNS-серверы и идентифицирующие поля правил сохраняются в `HKLM\SOFTWARE\KodVsego\SmartDns`, значение `AntigravityPreviousRules`, JSON схемы 1. Если копию не удаётся сохранить, замена не начинается. При снятии галочки списки DNS восстанавливаются, затем удаляются только наши добавленные правила. После перезапуска наличие копии отражается в галочке. При сбое установки выполняется откат; при неполном восстановлении оставшиеся записи копии сохраняются для повторной попытки. Если старый анлокер удалил правило или изменил его на новые сторонние настройки, восстановление сообщает об этом и не перезаписывает их.

Старый анлокер или его служба могут снова изменить DNS. Переход на прямой GeoHide отключает его локальный DNS-релей для этих доменов и может нарушить доступ к Antigravity. Режим не устанавливает замену его прокси, патчей или службы и не гарантирует работу приложения.

Реализация — `AgTakeover.cs`. В `tests/AgTakeover.Tests.cs` 16 проверок с имитацией записи: сохранение до изменения, частичные сбои, откат, повторное восстановление, сохранение чужих правок и ограничения области замены. Реальные правила при проверках не менялись. Предпросмотр диалога — `preview.ps1 -Dialog Force`.

В версии 2.7.3 исправлена обработка ответа при изменении NRPT: для Add/Set/Remove запрашивается PassThru, отсутствие возвращённого объекта после записи само по себе не считается ошибкой. Успех подтверждается повторным чтением правил; ненулевые коды Windows и отсутствие результата чтения остаются ошибками. Проверка создания/удаления выполняется также внутри Windows-адаптера. Если осталась копия уже восстановленных правил, снимите галочку для завершения восстановления. Статус обновляется перед открытием диалога ошибки и больше не остаётся на «Проверяем настройки…» во время сообщения.

В версии 2.7.4 напоминание «После смены DNS» не показывается при включении дополнительного DNS Antigravity. Оно остаётся только для основного переключателя DNS.

## Выбор и перезапуск браузера — версия 2.8

В напоминании «После смены DNS» появился список установленных браузеров и кнопка «Перезапустить». Поддерживаются Chrome, Edge, Firefox, Яндекс Браузер, Brave, Vivaldi и Opera. Список читается из регистраций приложений Windows и известных каталогов установки; реестр не изменяется. В команду запуска передаётся только проверенный абсолютный локальный путь EXE, без параметров из реестра.

После отдельного подтверждения программа отправляет обычный запрос закрытия видимых окон выбранного браузера в текущем сеансе Windows. Процессы сопоставляются по пути установки, а не только по имени. Если браузер завершился в течение 15 секунд и не запустился снова сам, он открывается заново. Если закрытие отменено, остаются фоновые процессы или доступ к процессам запрещён, перезапуск останавливается с сообщением. Принудительное завершение процессов не используется. Если браузер не работал, кнопка просто открывает его. Сохранение и восстановление вкладок зависит от настроек самого браузера.

Кнопка не запускает браузер из повышенного процесса: если весь переключатель открыт от администратора, нужно открыть его обычным способом. Запрос прав для смены DNS остаётся отдельным. Для Antigravity напоминание по-прежнему не показывается.

## Зашифрованный DNS — версия 2.16

Галочка «Зашифрованный DNS» включает системный DoH на поддерживаемой Windows 11. На старых Windows доступен обычный DNS, зашифрованный режим отказывается менять настройки, если Windows не предоставляет нужный API. Сейчас подтверждены сочетания адресов/шаблонов GeoHide RU (https://geohide.ru/dns-query) и Bezmezhau (https://dns.bezmezhau.com/dns-query). У Comss, GeoHide EU и Xbox галочка не включается: их сочетания адресов с системным DoH в этой версии не подтверждены. HTTPS-запросы к обоим поддерживаемым сервисам проверены из приложения.

Используется SetInterfaceDnsSettings с DNS_INTERFACE_SETTINGS3, DNS_SETTING_DOH и DNS_DOH_SERVER_SETTINGS_ENABLE (0x2), без FALLBACK_TO_UDP (0x4). Системные глобальные шаблоны DoH и политики Windows не редактируются. Перед включением выполняется HTTPS-запрос и проверка отдельных DNS-правил NRPT; при конфликте программа просит отключить DNS-настройку прежнего анлокера. Проверка NRPT не удаляет чужие правила. Добавление отдельной настройки Antigravity при активном DoH заблокировано, чтобы она не обходила шифрование.

Для исключения оставшихся IPv6 DNS привязка IPv6 временно выключается на затронутых адаптерах через штатный CIM API. Это явно указано под галочкой. Исходное состояние IPv6 и существующие параметры шифрования сохраняются до первой записи. Выключение DNS восстанавливает их. Снятие галочки при активном DNS переключает на обычный DNS и возвращает исходную привязку IPv6. Неудачное применение запускает откат; при неполном откате копия сохраняется. Автоматического перехода на UDP после неудачного HTTPS нет.

Расширенная резервная копия записывается со схемой 2, если содержит состояние привязки IPv6 или прежний DoH. Новая версия читает схемы 1 и 2. Старые версии, понимающие только схему 1, откажутся от восстановления расширенной копии; используйте 2.16 или новее. Это предотвращает потерю сведений о шифровании и IPv6 при запуске старого EXE.

В режиме DoH кнопка «Тест DNS» проверяет выбранный HTTPS endpoint. Автоматические проверки по UDP отключены. Сертификаты проверяются стандартным TLS Windows/.NET; HTTP-переадресации не принимаются. Тест показывает доступность endpoint, а не доказательство использования его всеми браузерами: собственные настройки DoH, VPN, расширения и будущие изменения политик могут работать отдельно от системного DNS.

Первопричина отказа этих провайдеров в запущенном пользователем EXE не воспроизведена: независимые чтения на доступном ПК работают. На доступном ПК чтение подтвердило два правила AG_UNLOCKER_NRPT_V2 для cloudcode-pa.googleapis.com и daily-cloudcode-pa.googleapis.com; они направляют DNS на 127.0.0.53 и внешние серверы независимо от DNS адаптера. В режиме DoH применяется отдельный адрес; он распознаётся при повторном чтении адаптеров, показывается в карточке DNS и учитывается при сбросе известных настроек без резервной копии. Для шифрования используется явный шаблон без UDP fallback.

Прежний безусловный запрет при любых правилах NRPT заменён выбором для известного частного случая. Если есть только одно или два точных локальных правила двух доменов Antigravity с меткой известного анлокера либо нашего приложения, диалог предлагает подключить DoH с сохранением Antigravity. После подтверждения шифруется DNS адаптера; запросы этих доменов продолжают идти по прежним правилам и НЕ объявляются зашифрованными нашим приложением. Карточка показывает «DoH · Antigravity по отдельным правилам». Это совместное использование с исключениями, а не устранение или шифрование сторонних правил. Чужие настройки вообще не изменяются.

Для полного шифрования всех системных запросов прежние отдельные правила нужно отключить в их программе. Неизвестные, общие, многодоменные, дублирующиеся и организационные политики не получают разрешения обхода. Подтверждение передаётся отдельной ограниченной операцией secure-keep-ag; повышенный процесс повторно читает и проверяет правила перед применением. Перед каждой новой операцией требуется новое подтверждение сохранения исключений. Обычная secure-enable по-прежнему отказывает при NRPT. IPv6 в режиме DoH по-прежнему временно приостанавливается и восстанавливается из резервной копии при выключении.

Проверено 209 сценариев с LiveHttps: отдельный адрес Comss и распознавание, применение и восстановление на имитации, ограниченная операция через служебный канал, допустимые исключения Antigravity и отказ опасных сочетаний. Реальные HTTPS-запросы ко всем трём DoH-сервисам успешны. Сетевые настройки пользователя и правила NRPT при разработке не менялись; реальное применение DoH не выполнялось.

## Удаление старых правил — версия 2.17.2

В карточке Antigravity добавлена кнопка «Удалить старые». При активном DoH нажатие на карточку со сторонними правилами также предлагает удаление вместо сообщения, блокирующего действие. Удаляются только точные локальные правила двух доменов с метками AG_UNLOCKER_NRPT_V2/AG_UNLOCKER_NRPT. Удаление подтверждается пользователем и выполняется отдельной ограниченной операцией ag-cleanup через служебный канал с повышением прав. Кнопка не удаляет правила неизвестных приложений, общие правила, политики организации или наши правила. Дублирующиеся и перекрывающиеся правила блокируют автоматическую очистку. Незавершённая копия предыдущей принудительной замены должна быть сначала восстановлена снятием галочки Antigravity.

До удаления всех выбранных правил выполняется полный экспорт их веток реестра штатным System32/reg.exe в отдельный новый каталог %ProgramData%\KodVsego\SmartDNS\RemovedAntigravityRules. Проверяются код завершения экспорта, заголовок и исходная ветка в .reg; файлы сбрасываются на диск до удаления. При ошибке копирования ничего не удаляется. Копия содержит все значения и типы, включая параметры, которые приложение не интерпретирует. После успешной операции кнопка меняется на «Копия правил» и открывает каталог. Возврат старых правил — вручную через .reg, согласно инструкции в каталоге. Выключение основного DNS не возвращает удалённые сторонние правила автоматически.

Перед каждым удалением повторно проверяются идентификатор, домен, метка, отображаемое имя и DNS-серверы; используется штатный NRPT-провайдер Windows Remove с проверкой реестра после записи. Повторное создание правил старым анлокером обнаруживается. При частичном отказе удаление останавливается; полная исходная копия сохраняется, ошибка сообщает её путь. Операция использует общий с Antigravity mutex.

Также устранён частный случай чтения пустой NRPT: Windows на доступном ПК после удаления последних правил возвращает CIM-ответ без кода/объекта. Теперь отсутствие правил подтверждается отдельным чтением реестра. Ненулевой код Windows, непустой реестр при отсутствующем ответе и ошибка независимого чтения остаются ошибками.

Проверки: 228 успешных сценариев, включая 16 имитаций удаления/ошибок/сохранения копии, передачу операции через служебный канал и 2 сценария подтверждения пустой NRPT. Проверка реального экспорта автоматически пропускается, если старых правил уже нет; при текущем прогоне это один пропуск. Реальные правила тестами не удалялись. Обнаружены сохранённые ранее копии двух старых правил в ProgramData. При контрольном чтении после их удаления список был пуст, что позволило проверить случай пустого ответа CIM. В последнем прогоне старых правил для повторного экспорта уже не было. Промежуточный EXE 2.17.1 оказался запущен и не перезаписывался; окончательный файл имеет версию 2.17.2.

## Почему DNS не гарантирует исправление региональной ошибки 400

Изучен confeden/Antigravity v2.24.0 (eac61a4), README.md, src/ls_log.rs, src/routes.rs и src/proxy.rs. Он распознаёт конкретную фразу user location is not supported в новых строках журналов Language Server, а реальную работу подтверждает streamGenerateContent + ResponseID. Обычный ответ DNS или неавторизованный HTTP-запрос этого не доказывает. Для исправления используется локальный прокси, клиентский патч и выбор маршрутов; маршрут с региональным отказом откладывается, а его соединения закрываются для следующей попытки. Данные части встроенных маршрутов не опубликованы. Удаление NRPT убирает старые исключения DNS, но не воспроизводит этот механизм и не гарантирует исчезновения 400. В нашем приложении монитор журнала, прокси и патч Antigravity не добавлялись. Подпись галочки изменена на «Может помочь при ошибке 400 в Antigravity».

## Автоперезапуск Antigravity — версия 2.18.0

После успешного включения дополнительных DNS Antigravity (включая подтверждённую принудительную замену старых правил) программа повторно проверяет реальный статус и выбранного провайдера, затем перезапускает уже работающее Antigravity. Обычное подтверждение включения предупреждает о перезапуске и необходимости сохранить изменения. Дополнительного диалога успешного перезапуска нет. Ошибка DNS, отмена UAC, неполный/неподтверждённый статус или простая повторная проверка не вызывают перезапуск. При выключении галочки или удалении старых правил автоматического перезапуска нет.

Используется существующий механизм обычного закрытия всех окон основного процесса с ожиданием завершения до 15 секунд. Принудительное завершение процессов не применяется. Если Antigravity ждёт сохранения или снова запущен другим процессом, новый экземпляр не создаётся; DNS остаётся применённым, а сообщение отдельно объясняет проблему перезапуска. Если Antigravity не был запущен, он не запускается. Разные одновременно открытые установки автоматически не перезапускаются. При запуске Smart DNS от администратора предлагается выполнить перезапуск вручную, чтобы Antigravity не получил повышенные права.

Повторно запускается тот же EXE из текущей пользовательской сессии. Из параметров сохраняются только проверенные существующие локальные --user-data-dir и --extensions-dir; произвольные отладочные флаги, команды, URL и аргументы дочерних процессов не копируются. Обычный профиль запускается без новых аргументов. Восстановление проектов, вкладок и окон зависит от настроек самого Antigravity.

Проверки: 7 новых сценариев — запуск только работающего приложения, порядок закрытия/открытия, ожидание сохранения, сохранение каталогов настроек без произвольных флагов, обычный профиль, отказ недостоверных параметров и проверка подтверждённого включения нужного провайдера. Реальное приложение при разработке не перезапускалось; закрытие/запуск проверялись на имитации процессов. Полный набор без LiveHttps: 232 успешных проверки, 1 пропуск реального экспорта при отсутствии старых правил.

## Отдельный главный статус Antigravity — версия 2.18.1

Если DNS адаптеров выключен, но наши два правила Antigravity полностью установлены, главный статус теперь показывает «Только Antigravity». Подпись указывает фактического провайдера этих правил и «общий DNS выключен», независимо от выбранной вкладки основного DNS. Кольцо выделено акцентом, а надпись на кнопке «ВКЛЮЧИТЬ DNS» объясняет действие: она включает общий DNS и не выключает правила Antigravity.

Неполная настройка показывается как «Antigravity частично», сторонние правила — «Правила Antigravity», ошибка чтения — «Проверьте Antigravity». Когда оба режима выключены, остаётся обычное «DNS выключен». Общий DNS, офлайн, VPN и текущая операция сохраняют прежний приоритет отображения. Статус правил Antigravity теперь перечитывается вместе с монитором сети каждые три секунды, чтобы изменения извне отражались без перезапуска окна. Эти статусы подтверждают установку правил, а не успешный ответ API Antigravity.

Проверка: сборка прошла; подготовлены изображения режима только Antigravity в обеих темах, частичного режима, сторонних правил и полностью выключенного DNS. В preview.ps1 добавлен -Inactive для независимого от настроек ПК предпросмотра. DNS-настройки и запущенные приложения при проверке не изменялись. Изменение касается отображения и чтения статуса, новых операций записи нет.
