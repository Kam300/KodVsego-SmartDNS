## Как пользоваться

1. Скачайте EXE и запустите. Установка не требуется.
2. Выберите провайдера. Стрелки и колесо мыши прокручивают список DNS.
3. Нажмите большую кнопку и подтвердите запрос администратора Windows.
4. Полностью перезапустите браузер или нужное приложение.
5. Для восстановления сохранённых настроек выключите DNS в программе.

Программа сохраняет исходные настройки адаптеров до изменения. Переключение провайдера эту копию не заменяет. При недоступном адаптере его копия остаётся для повторного восстановления. Неизвестные настройки, утраченные до создания копии, восстановить невозможно.



## Обычный и зашифрованный DNS

В Windows 2.23.5: устранена ложная блокировка DoH при локальной записи `DNS_RESILIENCY_slscr.update.microsoft.com` для Windows Update. Исключение допускается только при точном имени домена, локальном источнике, ожидаемых числовых полях Version=2/ConfigOptions=8 и корректных IP. Правила организации, широкие маски, другие домены и похожие записи по-прежнему проверяются как конфликты. Запись не удаляется и не меняется. DoH адаптера остаётся обязательным, но запросы Windows Update по этому отдельному правилу могут использовать его прежний DNS; исключение показывается в подписи и диагностике. Сообщение о неизвестном конфликте больше не приписывает любую запись прежнему анлокеру.

В Windows 2.23.5: в режиме DoH, если отдельных правил Antigravity нет, вместо лишней галочки показана карточка «Antigravity через DoH». До подключения она предлагает включить DNS большой кнопкой; после подтверждения показывает использование общего DNS. Карточка не открывает диалог и не создаёт правил. Управление уже существующими правилами и их очистка остаются доступны. Обычные подсказки показывают «Информация» и значок i вместо зелёной галочки «Готово»; успешные проверки сохраняют свой значок результата.

Обычный DNS доступен на поддерживаемых Windows 10 и 11. Системный DoH требует поддерживаемой Windows 11. Локальная DNS-служба для Windows 10 не устанавливается.

В Windows 2.23.3 исправлена проверка Comss DoH: запросы идут на настроенный адрес `195.133.25.16`, с исходным именем `dns.comss.one` для SNI и проверки сертификата. Проверке не требуется предварительно разрешать имя самого резолвера через текущий DNS. Это устраняет ложный провал при ответе `127.0.1.1` для `dns.comss.one`. В отчёт записываются фактический IP назначения, имя сертификата и длительность запросов. Настройки DNS и файл hosts при проверке не меняются.

Windows 2.23.3: проверки DoH используют WinHTTP с поддержкой HTTP/2 для всех провайдеров. При временной ошибке соединения выполняется одна повторная попытка. Для GeoHide повторная попытка отдельно проверяет его опубликованные через DNS IPv4-адреса по HTTPS с исходным именем сервера, проверкой сертификата и DNS-ответа. Это не переключение на обычный DNS и не другой провайдер. Из-за недоступных адресов проверка может занять несколько десятков секунд; ошибки сертификата, HTTP и повреждённые ответы не принимаются за успех. В лог попадают попытки, адреса, длительность и коды WinHTTP.

[Таблица провайдеров и адресов](../README.md#провайдеры). В Windows 2.23.3 DoH доступен для Comss.one, Bezmezhau, DNS-AI и MagicDNS. Для DoH Comss используется отдельный адрес 195.133.25.16. Xbox DNS работает без DoH; GeoHide и GeoHide EU отключены. Для DNS-AI шифрование обязательно.

При включении системного DoH привязка IPv6 на изменяемых адаптерах временно приостанавливается; её исходное состояние сохраняется для восстановления. VPN может использовать собственный DNS и мешать работе. Проверка VPN приблизительная: расширения браузера, прокси и VPN на роутере могут не определяться.

## Antigravity

«Доп. DNS Antigravity» задаёт правила для cloudcode-pa.googleapis.com и daily-cloudcode-pa.googleapis.com. В Windows 2.23.3 для этой опции доступны MagicDNS и Bezmezhau. Comss, GeoHide и GeoHide EU для отдельной опции отключены. Прежние правила GeoHide по-прежнему распознаются и могут быть отключены.

Для шифрования выберите MagicDNS, включите «Зашифрованный DNS» и подключитесь большой кнопкой. Antigravity будет использовать общий системный DoH с обязательным HTTPS для обоих IP MagicDNS. Отдельная галочка при выбранном шифровании новые обычные DNS-правила не создаёт. Старые отдельные правила нужно отключить для полного шифрования. DNS-AI также используется через общий системный DoH, без дополнительных правил.

Чтение сторонних правил с нестандартным именем ключа реестра больше не прерывает проверку Antigravity. Такие правила учитываются при проверке конфликтов; приложение не считает их собственными и не удаляет автоматически.

После подтверждённого включения программа пытается перезапустить уже работающий Antigravity. Сохраните изменения заранее. Принудительное завершение процессов не выполняется.

Windows 2.23.3: перезапуск нового Antigravity Desktop ждёт не только закрытия главного окна, но и завершения его `resources/bin/language_server.exe`, процессов отображения и GPU. Ожидание — до 30 секунд; затем выполняется короткая пауза и повторная проверка фоновых процессов. Если сервер завис или приложение запустилось снова, повторный запуск отменяется с пояснением. Проверка ограничена текущим сеансом Windows и точными путями выбранной установки, IDE и серверы из других каталогов не затрагиваются. Изолированные crashpad-обработчики не блокируют перезапуск.

Сохраняется уже использованный параметр `--disable-gpu`, если приложение было запущено с ним, и явные каталоги профиля/расширений. У нового процесса очищаются служебные переменные Electron, включающие режим Node/helper; прокси и остальные переменные окружения сохраняются. В диагностический отчёт добавляются этапы перезапуска и конкретная причина отказа, без исходных командных строк и путей профилей. Проверки покрывают медленный/зависший сервер, поздний повторный запуск и реальные безвредные процессы Windows. Проверка чёрного экрана на пользовательском Antigravity после этой правки ещё не выполнялась: запрос запуска приложения не считается подтверждением загрузки интерфейса.

При обнаружении прежних правил можно подтвердить замену с сохранением прежних DNS. Снятие галочки восстанавливает сохранённые настройки. Удаление известных старых правил — отдельная операция с предварительным экспортом в .reg; кнопка «Копия правил» открывает каталог копии. Чужие и организационные правила автоматически не удаляются.

Если включены только отдельные правила, основной DNS может быть выключен — интерфейс показывает «Только Antigravity». Настройка может помочь с ошибкой 400, но не гарантирует доступ к API или аккаунту.

## Что показывает тест DNS

В **2.23.6-test.4** выберите сервис и провайдера в «Тест DNS» и нажмите «Проверить». Проверка сайта и API выполняется без ключей, по адресам выбранного DNS. Показываются ошибки DNS, соединения и TLS, запрос входа, проверка браузера и явные ограничения сервиса. Системные настройки не меняются. [Что именно проверяется и какие есть ограничения](SERVICE-AVAILABILITY.md).

Выбор «Только DNS» проверяет ответы DNS-серверов: в обычном режиме напрямую, в зашифрованном — через HTTPS или TLS по выбранному режиму. Для DNS-AI запрашиваются в том числе домены сайта Gemini и API.

**Успешный DNS-ответ не означает, что сайт или модель работают.** Доступность выданного адреса по HTTPS, DNS браузера и ограничения аккаунта — отдельные вопросы. У DNS-AI наблюдалась ситуация, когда DNS Gemini отвечал, а соединение с выданным узлом завершалось тайм-аутом.

Если сайты не открываются, проверьте подключение к сети, отключите VPN, проверьте собственный DNS браузера и перезапустите приложение. Можно попробовать другого провайдера или выключить DNS в программе для восстановления прежних настроек.

## Перезапуск браузера

Диалог после смены DNS позволяет выбрать браузер. Программа пытается сохранить используемые профили и закрыть браузер штатно. Сохраните работу заранее: приватные окна не восстанавливаются, фоновые процессы и запросы сохранения могут помешать перезапуску. Принудительное завершение не выполняется.

## Отчёт разработчику

При техническом сбое доступна кнопка «Сохранить отчёт». Сохраните TXT и вручную отправьте его [@TotalCodeAdmin](https://t.me/TotalCodeAdmin), описав действие и ошибку. Автоматической отправки нет.

Отмена прав администратора, отсутствие сети, VPN и другие обычные ситуации не требуют отчёта. В диагностике есть версия, сведения о Windows, DNS и правилах; история браузера, аккаунты, содержимое файлов и чатов не собираются. Перед отправкой можно открыть TXT и проверить его содержимое.

## Разработка и состояние выпуска

Повторный запуск той же или более старой версии показывает работающее окно. Более новая версия штатно закрывает старую и ждёт её выхода, затем открывается сама. При отказе закрытия второе окно не запускается. Служебные процессы изменения DNS и обновления не блокируются.

Старые EXE без этой защиты могут запускаться повторно сами; новая версия распознаёт уже открытые окна старых версий, но не меняет их поведение при последующем запуске.

Сборка из корня: build.bat. Версия задаётся в AssemblyInfo.cs. Тесты: powershell -NoProfile -ExecutionPolicy Bypass -File tests\run.ps1.

В версии 2.22.0 исправлена отзывчивость окна и отрисовка при большом масштабе экрана. Добавлены [режим «Авто»](AUTO.md) и [проверка и установка обновлений](UPDATES.md). История доступна в [коммитах](https://github.com/Kam300/KodVsego-SmartDNS/commits/main/) и [релизах](https://github.com/Kam300/KodVsego-SmartDNS/releases).

Основа проекта — [hb-ai-xbox-dns](https://github.com/neiroseti-ai/hb-ai-xbox-dns/). Исходная MIT-лицензия и уведомления правообладателей сохранены в [LICENSE](../LICENSE). Это сведения о происхождении кода, а не канал поддержки текущей версии.

Повторный запуск: более новая версия штатно закрывает старую и ждёт её выхода до 15 секунд. Та же или более старая версия только показывает работающее окно. При отказе закрытия или тайм-ауте второе окно не открывается. Принудительное завершение процессов не используется.
