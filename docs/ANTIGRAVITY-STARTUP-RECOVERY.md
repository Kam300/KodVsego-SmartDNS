# Восстановление чёрного окна Antigravity

В Windows-сборке 2.23.7-test.4 Smart DNS может повторить неудавшуюся загрузку окна нового Antigravity Desktop. Включается в **Настройки → Общие → Восстанавливать чёрное окно Antigravity**; по умолчанию включено. Работает, пока Smart DNS открыт, в том числе когда он свёрнут.

Это исправляет наблюдавшуюся последовательность: оболочка получила тайм-аут при первой загрузке локального HTTPS, Language Server позднее стал отвечать, но оболочка осталась на странице ошибки до ручного Ctrl+R.

## Условия автоматического восстановления

1. Порт отладки прочитан из стандартного профиля Antigravity и принадлежит его процессу в текущем сеансе Windows. Файл порта не старше текущего запуска. Профиль IDE и нестандартный `--user-data-dir` этим механизмом не обслуживаются.
2. Основной документ окна — именно `chrome-error://chromewebdata/`, а недоступная страница находится на `https://127.0.0.1:<port>`.
3. Локальный HTTPS-порт принадлежит Language Server соответствующей установки. Ответ `200` получен дважды с интервалом между опросами.
4. Непосредственно перед командой окно проверяется ещё раз. Если пользователь уже восстановил окно или открыл рабочую страницу, перезагрузка отменяется.

Перезагружается только страница через штатный `Page.reload`. Процессы клиента не завершаются, ввод в чат не выполняется, профиль и кэш не удаляются. Применяется не более двух попыток на окно, с паузой не менее 20 секунд. Успешный ответ модели и ошибку 400 этот механизм не определяет.

Не изменяются DNS, прокси, службы, сертификаты Windows и файлы установленного Antigravity. Самоподписанный сертификат допускается только при диагностическом TLS-соединении с проверенным локальным процессом Language Server; глобальная проверка сертификатов и удалённые HTTPS-соединения не затрагиваются. В журнал не записываются полные URL чатов, их идентификаторы, токены и содержимое страниц.

Если Language Server завершился, не сообщил порт, сам сервер так и не начал отвечать или локальная отладка недоступна, автоматическая повторная загрузка не выполняется. Этот механизм устраняет застревание на уже неактуальной странице ошибки, но не ускоряет внутреннюю инициализацию Language Server.

## Проверка

Политика восстановления проверена на подставных страницах: ожидание готовности, две успешные пробы, сохранение рабочего документа, отмена, гонка с ручным восстановлением и ограничение числа попыток. Владение TCP-портом проверено на отдельном loopback-слушателе. На реально работающем Antigravity проверены чтение состояния страницы и готовность локального TLS-сервера; рабочая страница при этом не перезагружалась. Настоящее окно с первоначальным тайм-аутом ранее успешно восстановилось ручным Ctrl+R.

Дополнительно выполнен разрешённый пользователем повторный запуск под наблюдением того же механизма. В течение трёх минут наблюдения прежний тайм-аут не повторился; дерево доступности подтвердило рабочий интерфейс разговора и поле ввода. Автоматическая перезагрузка не потребовалась. Поэтому повторное восстановление настоящей страницы ошибки пока подтверждено политическими тестами и ручным Ctrl+R, а не заявлено как воспроизведённый сквозной автоматический тест. Локальная проверка HTTPS в новом коде отдельно прошла на настоящем Language Server; используется TLS 1.2 без изменения глобальных настроек .NET.
