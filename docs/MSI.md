# Установщик MSI

MSI — основной установщик Windows начиная с **2.23.2**. Стандартный набор также содержит портативный ZIP и отдельный EXE для совместимости с обновлениями. [Сборка всего набора](DISTRIBUTION.md). Требования MSI: Windows 10 2004+ или Windows 11, x64, .NET Framework 4.8.

MSI устанавливает приложение для текущего пользователя в `%LOCALAPPDATA%\Programs\KodVsego\SmartDNS-MSI`, создаёт ярлык **Smart DNS (MSI)** в меню «Пуск» и запись удаления в настройках Windows. Установка не запрашивает повышение прав, не запускает приложение и не меняет DNS. Старый EXE-установщик использует другую папку; его установка сохраняется. Настройки приложения и резервные копии общие с прежней копией.

Перед установкой или обновлением закройте Smart DNS. Новый MSI обновляет предыдущую MSI-установку. Старый продукт удаляется после установки новых файлов, внутри транзакции Windows Installer. Более старый пакет блокируется. Повторное открытие установленного MSI предлагает восстановление файлов или удаление. Для удаления также подходит список установленных приложений Windows. Перед удалением выключите DNS в программе, если хотите восстановить прежние настройки сети: само удаление их не меняет. Пользовательские файлы и резервные копии сохраняются.

В MSI-варианте встроенная проверка обновлений сохраняется, но кнопка открывает страницу релиза GitHub. Установить обновление нужно новым MSI: замена одного EXE обошла бы учёт файлов Windows Installer. Автоматическая загрузка и запуск нового MSI пока не реализованы. В старых релизах MSI может отсутствовать. Портативная версия и Inno Setup сохраняют прежний способ обновления.

## Проверка антивирусами

MSI содержит один EXE приложения, признак MSI-установки, памятку и пять файлов лицензий. Установщик использует стандартные действия Windows Installer: в таблице `CustomAction` нет действий, отсутствуют установочные скрипты и автоматический запуск приложения. EXE собран проверяемым Roslyn-процессом из исходников с явным списком ресурсов и зависимостей.

Это уменьшает количество собственного установочного кода, но **не доказывает безопасность и не гарантирует уменьшение детектов**. MSI и EXE не подписаны сертификатом издателя. По сообщению пользователя, при проверке **2.23.2-test.2** MSI получил 0 срабатываний, ZIP — 1, отдельный EXE — менее 3, установщик EXE — 5. Это результаты конкретных файлов на момент проверки. Для проверенного MSI SHA-256: `19862c790e401451fb465f061aaa36bb74c6e09556bb5315af0df99780ae4bb9`. Новый MSI при повторной сборке может иметь другую контрольную сумму и требует отдельной проверки. Скрипты не загружают файлы на VirusTotal автоматически.

## Сборка

Используется закреплённая версия WiX CLI 5.0.2, без платных служб и расширений. Нужен .NET SDK и подписанный Microsoft Roslyn из Visual Studio / Build Tools. Перед постоянным выпуском нужно отдельно пересмотреть поддерживаемую ветку WiX.

```powershell
dotnet tool install wix --version 5.0.2 --tool-path "$env:LOCALAPPDATA\KodVsego\BuildTools\wix-5.0.2" --allow-roll-forward --source https://api.nuget.org/v3/index.json
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-msi.ps1
```

Отдельная команда `build-msi.ps1` создаёт только MSI и материалы сборки в `dist/<версия>/`. Для стандартного набора используйте `build-distribution.ps1`: он создаёт MSI, ZIP и EXE в `dist/<версия>/release` и проверяет состав приложения. В обоих случаях файлы не загружаются на внешние сервисы. Для проверки упаковки можно передать готовый EXE через `-SourceExe`; отдельный `build-msi.ps1` в этом режиме повторно не проверяет состав приложения.

Windows Installer сравнивает только три числовые части версии. Отображаемая версия приложения остаётся обычной; внутренняя версия MSI преобразуется так:

| Версия приложения | Версия MSI | AssemblyFileVersion |
| --- | --- | --- |
| 2.23.2-test.1 | 2.23.2001 | 2.23.2001.0 |
| 2.23.2-test.2 | 2.23.2002 | 2.23.2002.0 |
| 2.23.2 | 2.23.2999 | 2.23.2999.0 |
| 2.23.3-test.1 | 2.23.3001 | 2.23.3001.0 |

Поддерживаются `test.1`–`test.998`; третья часть версии приложения — 0–64. Перед выпуском нужно согласованно изменить `AssemblyInformationalVersion`, `AssemblyFileVersion` и имя результата в `build.bat`. `AssemblyVersion` может сохранять обычный формат. Сборщик MSI проверяет `AssemblyFileVersion`: стабильный EXE должен иметь большую файловую версию, чем тестовый, иначе Windows Installer может сохранить прежние байты.

`UpgradeCode` постоянен для MSI-семейства, `ProductCode` меняется с версией. Повторная сборка одной версии сохраняет `ProductCode`; для выпуска изменённых файлов следует повысить версию. Двоичная воспроизводимость самого MSI не заявляется.

## Проверки

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\MsiPackaging.Tests.ps1
powershell.exe -NoProfile -Command "& './tests/run.ps1' -Only @('AppUpdateTests','SingleInstanceTests','BrowserTests')"
```

Проверка MSI изучает таблицы фактически собранного пакета и создаёт отдельное тестовое семейство из безвредных EXE. Проверяются установка, точные байты приложения и лицензии, ярлык, восстановление повреждённого файла, обновление с сохранением пути, запрет понижения версии, сохранение предыдущей установки при намеренно недоступном CAB в одноразовом пакете, переход с тестовой сборки на стабильную и удаление с сохранением постороннего файла. Идентификаторы и пути тестов уникальны; рабочая установка приложения и DNS не меняются. Ключ `-SkipInstallation` ограничивает проверку структурой MSI и порядком версий.

Тесты обновления отдельно проверяют, что признак MSI запрещает замену EXE и запуск помощника обновления, а ссылка ведёт на точную страницу стабильного релиза. Это не проверка реального сетевого доступа к сервисам и не результат антивирусного сканирования.

Автоматическая визуальная проверка мастера не завершена: инструмент управления окнами блокирует `msiexec.exe`. Таблицы диалогов и их порядок проверены, а запуск мастера тестового пакета завершился успешной установкой по журналу Windows Installer. Этот тестовый продукт затем удалён.

Справочные источники: [Windows Installer](https://learn.microsoft.com/en-us/windows/win32/msi/windows-installer-portal), [сравнение версий MSI](https://learn.microsoft.com/en-us/windows/win32/msi/productversion), [обновление и откат WiX](https://docs.firegiant.com/wix/schema/wxs/majorupgrade/).
