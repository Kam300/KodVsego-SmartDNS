## Проверка HTTPS Gemini

Для всех 11 профилей, в метаданных которых присутствует Gemini (включая отключённые), получены адреса сайта и API через ответивший DNS. Выполнены 22 HTTPS-запроса непосредственно к полученным адресам с исходным Host/SNI и проверкой сертификата: сайт `/` ответил HTTP 200, API `/v1beta/models` — HTTP 403 с сообщением `unregistered callers` / `PERMISSION_DENIED`. Для GeoHide US использован ответ единственного доступного UDP-сервера.

Ответ API означает необходимость ключа/авторизации; его нельзя выдавать за сбой DNS или за успешную генерацию. Вход в Google-аккаунт, генерация, регион аккаунта, браузерный Secure DNS и доступ из другой сети не проверялись. IP, возвращённый для Gemini, может быть прокси провайдера: такой адрес нельзя автоматически добавлять в список DNS-серверов.

## Изменение приложений

- В общем `config/providers.json` у Comss, GeoHide RU/EU и Bezmezhau добавлен тест `gemini.google.com`, у MagicDNS — `generativelanguage.googleapis.com`. Теперь все профили с заявленной поддержкой Gemini проверяют и сайт, и API.
- Исправлена устаревшая строка Comss в README: основной адрес приведён к уже используемому приложениями `94.250.253.55`.
- Пересозданы общий удалённый каталог и встроенные снимки Windows/Android без изменения ID, IP, протоколов и пользовательских настроек. Добавлены проверки полноты Gemini-доменов в тесты обеих платформ.
- Это улучшение диагностики; оно не меняет маршруты внутри DNS-провайдеров и не обещает восстановление Gemini там, где оператор перестал его обслуживать.
- Приложения с поддержкой удалённого каталога смогут получить новую ревизию при проверке обновлений адресов. Установленный APK 1.5.1 этого механизма не содержит: ему нужна новая сборка Android. Изменение `main` не заменяет уже опубликованные APK/EXE.
