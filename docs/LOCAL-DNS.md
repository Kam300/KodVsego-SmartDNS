# Локальный DNS · совместимость · beta

На главном экране нажмите **«Способ подключения» → «2 · Через приложение»**, затем выберите провайдера. Программа сама шифрует DNS; её нужно держать открытой. Большая кнопка запускает/останавливает режим без дополнительного окна. Windows запросит права для отдельного обработчика. Выбор режима запоминается, но запуск приложения сам по себе DNS не включает. HTTPS выбирается при переходе в этот режим; HTTPS и TLS выбираются в соседнем поле **«Шифрование»** на главном экране. Выбор применяется при следующем включении DNS большой кнопкой. Во время подключения оба поля заблокированы.

Для первого теста рекомендуется **DNS-AI → Через приложение → HTTPS** — это соответствует схеме локального DoH, которую пользователь успешно проверил в приложении DNS-AI. Перед запуском выключите DNS в другом приложении и дождитесь его восстановления. Простое закрытие сторонней программы может оставить `127.0.0.1` без слушателя. Если loopback уже установлен сторонней программой или порт UDP/TCP 53 занят, Smart DNS откажется применять настройки.

## Авто в способе подключения 2

В 2.23.6-test.23 первым пунктом списка доступно **«Авто · beta»**. Выберите сервис, запустите подбор и подключите выбранный DNS. Подбор проверяет только зашифрованные варианты с текущим HTTPS или TLS; обычный DNS не используется как запасной способ. Пока идёт проверка, настройки сети не меняются. Выбранный результат запускается через локальный обработчик `127.0.0.1` / `::1`, без перехода на системный режим Windows или виртуальный адаптер Gemini. Подробности и протокол доступны в копировании результатов и общем журнале.

Сервис по умолчанию из настроек действует и для этого способа: большая кнопка запускает подбор для него. Ручной выбор провайдера отменяет Авто на текущий сеанс. Запуск самой программы по-прежнему не включает DNS. После остановки, смены сети или ошибки обработчика нет фонового переподключения; для нового подбора нужно действие пользователя. Во время работы обработчика выбор другого DNS заблокирован.

Отдельная настройка Antigravity сохраняет своего провайдера. Если она включена, Авто основного DNS нельзя использовать как проверку отдельного маршрута Antigravity: приложение объясняет это до сетевых запросов. Можно выбрать другую цель Авто либо выключить отдельный маршрут и подбирать общий DNS для Antigravity. Проверка доступности без ключа не доказывает ответ модели или работу аккаунта.

## Путь запроса

### Обрыв канала управления в test.24

Подтверждённая итоговая ошибка обработчика сохраняется, даже если последующее закрытие потока даёт `IOException: Канал нарушен`. После сообщения `STOPPED` такое исключение при освобождении потока не превращается в новую ошибку. Обрыв без итогового сообщения считается нештатным даже при коде процесса 0. Пока обработчик завершает работу, интерфейс снимает статус подключения и блокирует повторный запуск. Наличие ожидающего восстановления проверяется перед сообщением об успешном завершении; автоматического переподключения нет.

Журнал содержит `CONTROL stage`, HRESULT, код завершения процесса, наличие итогового ответа и флаг незавершённого восстановления. Локальный обработчик отдельно отмечает запуск слушателей, зашифрованную проверку, запуск процесса восстановления, применение/проверку настроек и восстановление. Если запуск снова завершится ошибкой, экспортируйте журнал через настройки: по одному скриншоту канала нельзя определить сетевую причину отказа.

### Отдельный Antigravity в test.18

В локальном режиме возвращён отдельный переключатель **«Antigravity · отдельно»** и выбор его провайдера справа. Можно оставить общий DNS-AI и направить только `cloudcode-pa.googleapis.com` и `daily-cloudcode-pa.googleapis.com` через MagicDNS (начальный выбор), Bezmezhau или DNS-AI. Вход в аккаунт Google, Gemini, ChatGPT и остальные домены продолжают использовать основной DNS. Имена сопоставляются точно, без захвата соседних доменов; обрабатываются все типы записей. Отдельный путь всегда использует DoH независимо от HTTPS/TLS основного провайдера.

Настройка включается пользователем, а не автоматически с общим DNS. Изменить галочку/провайдера можно при выключенном локальном режиме. Нажмите большую кнопку после выбора: до изменения адаптеров оба API-домена должны вернуть корректный DNS-ответ через отдельного провайдера. Ошибка не подменяется общим или открытым DNS. В журнал попадают отдельный провайдер, домены и полученные адреса. NRPT для этого маршрута не создаётся — раздельный выбор выполняет локальный сервер. Старые отдельные NRPT-правила необходимо сначала выключить в программе, которая их создала; конфликтующие правила автоматически не удаляются.

Надпись «общий DNS настроен» больше не представляется как работоспособность Antigravity. DNS-preflight **не проверяет** ответ модели, авторизацию или доступность региона аккаунта. Ошибка API `400 User location is not supported` может сохраниться при корректном DNS: это не доказательство успешного обхода регионального ограничения. Новое приложение/IDE/CLI могут требовать дополнительных действий с клиентом или его соединениями. Для сравнения [референсный Antigravity Unlocker](https://github.com/confeden/Antigravity#что-меняется-в-системе) включает не только DNS, но и клиентскую/прокси-часть. Smart DNS не переносит эти патчи, не меняет файлы Antigravity, аккаунт или proxy-переменные и не извлекает его токены. После изменения маршрута Antigravity следует перезапустить вручную для нового соединения.

`Windows → 127.0.0.1:53 / [::1]:53 → обработчик Smart DNS → выбранный DoH или DoT`

Локальный участок обычного DNS не выходит за пределы ПК. Дальнейшее шифрование выполняет собственный транспорт приложения, который подключается к адресам каталога и проверяет сертификат исходного имени DNS-сервера. Открытого upstream DNS и отключения проверки сертификатов нет. Виртуальный адаптер Wintun не создаётся, драйвер не загружается, маршруты и правила брандмауэра не добавляются. Внешний IP остаётся прежним. Это DNS всего ПК, а не разделение приложений. Собственный DoH браузера может идти отдельно.

Самостоятельная реализация на C# использует существующие `TunnelUpstream`, проверку DNS-пакетов и движок резервных копий проекта. Исходники GPL-проекта confeden/DNS-AI не переносились. [DNS-AI](https://github.com/confeden/DNS-AI) использовался для изучения работающей у пользователя архитектуры.

## Запуск и остановка

1. Проверяются другой VPN, отдельные DNS-правила и исходные настройки активных физических Wi-Fi/Ethernet с шлюзом. Неизвестный loopback в исходных DNS отклоняется.
2. Эксклюзивно открываются только loopback UDP/TCP-сокеты. Нужные слушатели IPv4/IPv6 обязаны быть доступны. До изменений адаптеров проверяются реальные локальные запросы по обоим транспортам.
3. Поднимается отдельный процесс восстановления с теми же повышенными правами. Только после его готовности записывается маркер конкретного сеанса и список адаптеров. Исходные DNS сохраняются на диск до первой записи через существующий движок резервных копий.
4. Адаптеры направляются на `127.0.0.1` и `::1`. Встроенные DoH/DoT-свойства этих адресов очищаются, поэтому шифрованием занимается обработчик приложения. Состояние привязки IPv6 не выключается. Проверяется локальный сервер и системное разрешение имён; неудача откатывает настройки.
5. При остановке сначала восстанавливаются исходные DNS и их свойства, затем закрываются локальные сокеты. Не связанные с сеансом копии других/недоступных адаптеров сохраняются.

Фоновые проверки фактического DNS и сохранение полного журнала из test.16 доступны и в этом режиме. Журнал содержит этапы запуска, провайдера/протокол, счётчики и результат восстановления. Названия произвольных посещаемых доменов не записываются. В «Тест DNS» проверка обычного выбранного провайдера и проверка системного пути остаются отдельными вариантами.

## Сбои и границы восстановления

Приватные IPC-каналы ограничены SID пользователя/администраторами; стороны проверяют PID и путь исполняемого файла. Процесс восстановления ожидает закрытия канала, в том числе при принудительном завершении обработчика. Он берёт общий mutex и восстанавливает только сеанс с совпадающим сохранённым идентификатором владельца. Запоздавший процесс прежнего сеанса не может восстановить новый. Неудачное восстановление сохраняет копии и маркер для следующей попытки. Обработчик также прекращает работу при потере своего процесса восстановления.

При нормальном закрытии главное окно ждёт остановки. При исчезновении главного процесса обработчик обнаруживает закрытие канала и восстанавливает DNS. При полном отключении питания, завершении всех процессов или запрете Windows на запись мгновенное восстановление невозможно: данные остаются в реестре. После повторного запуска и включения режима обработчик **сначала** пытается восстановить прежние DNS. При ошибке восстановления новый режим не применяется. Пользовательские/системные ограничения записи нельзя обойти гарантией приложения.

При изменении подключения режим останавливается и восстанавливает настройки своего набора адаптеров; к новому адаптеру DNS автоматически не применяется. При недоступном зашифрованном upstream локальный сервер возвращает SERVFAIL, а не переходит на незашифрованный DNS.

## Ограничения нагрузки и тесты

Одновременно обслуживается не более 32 запросов/клиентов. TCP имеет тайм-аут чтения/записи и ограничение числа запросов на соединение; размеры DNS ограничены протоколом. Превышение UDP-размера клиента возвращает TC для повторения через TCP. Ответы DNS, включая AAAA, HTTPS, NXDOMAIN и DNSSEC-поля, передаются без добавления собственного кэша или переписывания адресов.

`tests/LocalDns.Tests.cs` проверяет настоящий обмен по loopback на случайных свободных портах с искусственным upstream, TCP-фрагментацию и повторное использование соединения, IPv4/IPv6, занятый порт, SERVFAIL/NXDOMAIN, EDNS/TC, порядок запуска/отката, отмену, сохранение чужих резервных копий и отказ сохранять неизвестный loopback. Отдельный тест принудительно завершает только свой тестовый процесс: реальный управляющий канал закрывается, путь восстановления вызывается с искусственными настройками. Повышенные процессы восстановления, запись DNS реальных адаптеров и запуск драйвера тестами не выполняются. Окончательное включение/выключение на проблемном ПК проверяется пользователем.
