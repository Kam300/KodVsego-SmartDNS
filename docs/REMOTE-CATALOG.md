# Обновление каталога DNS на Windows и Android

Приложения читают один файл данных: `config/catalog.json` в ветке `main` репозитория Kam300/KodVsego-SmartDNS. Ссылка фиксирована в исходниках. Установка новой версии приложения требуется один раз, чтобы появилась поддержка каталога; дальнейшие изменения адресов не требуют новой сборки.

## Что видит пользователь

В настройках Windows (Общие) и Android доступна галочка **«Обновлять адреса DNS автоматически»**, краткий статус и ручная проверка рядом — без отдельного окна. На Windows галочка сохраняется кнопкой «Сохранить»; «Отмена» отбрасывает изменение. На Android переключатель сохраняется сразу, как остальные общие настройки. По умолчанию проверка включена. Приложение проверяет при открытии, не чаще раза в сутки, включая неудачные попытки. Ручная кнопка обходит суточное ограничение.

Загружается только JSON: IP, DoH, DoT, bootstrap, описания, доступность провайдеров и адреса уже поддерживаемых чекеров. Новое поведение чекера требует новой версии программы. Автообновление не выполняет код, не устанавливает приложение и не перезапускает другие программы.

Обновление сначала сохраняется как ожидающее. Пока DNS включён, подключается, переключается или идёт тест, новая конфигурация не применяется. В Windows дополнительно ожидается завершение восстановления резервных копий и возврат на главный экран. В Android ожидается закрытие диалогов. Затем используется новая версия при следующем подключении. Активный DNS самопроизвольно не переподключается.

Пользовательские DNS Windows хранятся отдельно и не перезаписываются. Выбор и видимость встроенных провайдеров привязаны к стабильным ID. Удалённый каталог не может заново включить исторические GeoHide RU/EU и Xbox.

При недоступности GitHub, неверных данных или повреждении кэша остаётся последняя принятая копия; при повреждённой копии на диске используется встроенная. Проверяются размер до 256 КиБ, схема, возрастающая ревизия, стабильные ID/key, публичные числовые IP, HTTPS/DoT, пределы списков и известные виды чекеров. При равной ревизии изменённое содержимое не принимается. Эти проверки не доказывают добросовестность DNS-сервиса: источник доверия — управляемый репозиторий и HTTPS GitHub, отдельной криптографической подписи каталога сейчас нет.

Windows хранит данные в `%LOCALAPPDATA%/KodVsego/SmartDns/catalog`; Android — в приватной папке `files/catalog`. Передаются обычные HTTPS-запросы за каталогом; журнал и история DNS к ним не прикрепляются.

## Как поддерживать адреса

1. Проверить официальную страницу нужного профиля, отдельно обычные DNS, DoH bootstrap и DoT. Страница может перечислять разные серверы для разных режимов.
2. Изменить `config/providers.json`, сохранив ID/key. Новые провайдеры можно только добавлять в конец (до 64 встроенных записей). Старые адреса добавлять в `legacyIpv4` для распознавания прежних настроек. Скрывать через `enabled`, не удалять строки и не менять порядок.
3. Для смены адреса уже реализованного чекера изменить `config/provider-checkers.json`. Новый `kind` требует реализации на обеих платформах.
4. Выполнить из корня `./tools/Sync-ProviderAvailability.ps1`. Скрипт создаст нормализованный `config/catalog.json`, новую монотонную ревизию и встроенные снимки C#/Java. Повторный запуск без изменений сохраняет ревизию. Редактировать сгенерированные снимки вручную не нужно.
5. Запустить Windows `./tests/run.ps1 -Only CatalogUpdateTests,ProviderCheckTests,CustomDnsTests` и Android `./gradlew testDebugUnitTest lintDebug --no-daemon --no-watch-fs`. Проверить diff, затем опубликовать файлы в `main` после ревью. Данные не становятся доступными удалённо от одной локальной сборки.

## Наблюдение за официальными сайтами

Workflow `.github/workflows/watch-provider-catalog.yml` запускается ежедневно и вручную. Он читает информационные URL доступных провайдеров из конфигурации, извлекает опубликованные IP/DoH и явно указанные `tls://`-имена. Для статических приложений разрешено прочитать до двух JS-файлов `/assets/` того же сайта без выполнения кода. Для статического объявления WLrus поддержан его шаблон `DNS_HOST`. Динамическая страница, новый формат или отказ сайта требуют ручной проверки.

Изменение наблюдений создаёт PR с `config/provider-observations.json` и `docs/PROVIDER-CATALOG-PROPOSAL.md`. Эти файлы **никогда не читаются приложениями**. Список кандидатов может содержать примеры адресов и несколько профилей; поддерживающий разработчик проверяет его и вносит точное изменение в основной каталог по шагам выше. Автоматического слияния и публикации найденных адресов нет. Пока открыт PR, workflow не переписывает его ветку; новый отчёт сохраняется артефактом Actions.

Для создания PR нужны разрешения репозитория **Actions → General → Allow GitHub Actions to create and approve pull requests**. Сам workflow не одобряет и не сливает PR. GitHub расписание запускается только после публикации workflow в основной ветке. До публикации доступна встроенная локальная копия.

Проверка наблюдателя без сети: `python -m unittest discover -s tests -p test_provider_watcher.py`. Ручной сбор наблюдений: `python tools/watch_provider_catalog.py`. Тайм-аут или пустая страница не стирают сохранённые данные и не выключают провайдера.
