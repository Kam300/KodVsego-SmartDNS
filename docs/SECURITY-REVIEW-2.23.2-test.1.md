## Повторная сборка EXE

В новую отдельную папку перенесены только 43 явно перечисленных входных файла: исходники, каталог DNS, манифест, лицензии, шрифты, значки и сборочные файлы. Готовые EXE из проекта не копировались. Каталог провайдеров заново сгенерирован из JSON. Выполнен тот же `build.bat` системным C#-компилятором.

Повторная сборка дала EXE того же размера — 608256 байт. Сравнение всех байтов показало совпадение после исключения из сравнения:

- 4 байт времени сборки в COFF-заголовке;
- 16 байт MVID модуля;
- 36 символов того же GUID в имени автоматически созданного компилятором типа `<PrivateImplementationDetails>`.

Маскирование выполнялось только в копиях массивов в памяти для сравнения. EXE не переписывались и не изменялись для обхода антивирусов.

SHA-256 обеих нормализованных копий: `c8d13b333a0207a5491eb3e46aaa85653cf70cc25d3189ff29acb1c049bc689b`. Это технический хеш сравнения, а не хеш распространяемого файла.

Остальные байты, включая код, метаданные, строки и все 15 встроенных ресурсов, совпали. Встроены 5 лицензий, ICO, 3 шрифта и 6 PNG значков сервисов. Ссылки сборки — только `mscorlib`, `System`, `System.Core`, `System.Drawing`, `System.Windows.Forms`, `System.Management`, `System.Web.Extensions` и `Microsoft.Management.Infrastructure`. Это проверка ссылок и воспроизводимости на этом компьютере, а не независимое доказательство безопасности каждой системной DLL.

## Компоненты сборки и установщик

- Authenticode системного `csc.exe`: действительна, издатель Microsoft Windows.
- Authenticode исходного установщика Inno Setup 6.7.3, ISCC.exe, ISCmplr.dll и ISSigTool.exe: действительна, издатель Pyrsys B.V.
- Все 17 компонентов с `.issig`, в том числе Setup.e32 и SetupLdr.e32/e64, прошли криптографическую проверку ISSigTool с публичными ключами def01/def02, скачанными с официального сайта Inno Setup. Одного совпадения хеша рядом лежащего `.issig` для такого вывода было бы недостаточно.
- Сценарий Inno включает EXE приложения и лицензии; ярлыки, обычную запись удаления Windows и запуск после установки только по отмеченной пользователем опции. Нет встроенной загрузки дополнительных программ или PowerShell-скрипта установки.
- Установщик повторно собран из отдельной папки с проверенными компонентами. Установка, переустановка и удаление проверены на отдельном тестовом AppId и во временной папке. Байты установленного приложения совпали с переданным EXE. Рабочая копия приложения и её настройки не изменялись.
- Три проверки ограничения поиска DLL прошли: каталог рядом с EXE, текущая папка и PATH не используются обычным поиском нативных DLL; системная DLL загружается штатно.

Метод проверки компонентов: [официальная инструкция Inno Setup](https://jrsoftware.org/isdl-verify.php).

## Что остаётся невыясненным

В полученной сводке поведения EXE есть метки загрузки DLL из подозрительной папки, чтения памяти процесса, RWX-памяти, anti-sandbox/unhook и запуска CLR из динамической памяти. Сводка не содержит достаточного стека и происхождения вызовов, чтобы надёжно отнести каждое действие к коду приложения, системной среде .NET или инструментам песочницы. Объявлять их безвредными только из-за использования .NET нельзя.

Среди показанных сетевых запросов EXE — `api.github.com` и `example.com`. Это соответствует проверке обновления и соединения, но не является полным доказательством отсутствия других сетевых действий. Песочница запускает приложение в ограниченном сценарии; проверка UAC, применения DNS и ручного обновления этим отчётом не покрывается.

Целевой поиск в исходниках приложения не нашёл явных вызовов ReadProcessMemory, WriteProcessMemory, VirtualAlloc/VirtualProtect, загрузки mscoree или удаления перехватчиков. Это не исключает соответствующие действия внутри системной среды исполнения и не заменяет трассировку.

Изолированной Windows VM или Windows Sandbox в доступном окружении не обнаружено. Повторная сборка в новой папке выполнена на том же Windows-компьютере и не должна называться сборкой в чистой ОС. В проекте уже есть GitHub Actions с `windows-latest`; он не запускался для локальных незапушенных изменений. Новые коммиты, отправка в GitHub и релизы не выполнялись.

Вывод: подмена готового EXE относительно текущих входных файлов и подмена проверенных компонентов Inno не обнаружены проведёнными проверками. Причина Wacatac и остальных вердиктов не установлена. Без независимой среды и подробной трассировки нельзя обещать снижение числа срабатываний или считать файл безусловно безопасным.

## Повторная проверка отчётов разработчиком

`tools/Get-VirusTotalReport.ps1` читает существующий отчёт по хешу локального файла. Получает ключ через параметр `-ApiKey` типа SecureString либо переменную текущего процесса `VIRUSTOTAL_API_KEY`. Значения ключей в команды, документацию, Git и отчёты добавлять не нужно. Скрипт не загружает файл и не запускает повторный анализ; при отсутствии отчёта сообщает об этом. При лимите API прекращает запросы.

Пример после передачи ключа в процесс безопасным способом:

```powershell
./tools/Get-VirusTotalReport.ps1 -File ./dist/2.23.2-test.1/KodVsego_SmartDNS.2.23.2-test.1.exe
```

Пять проверок клиента выполняются с искусственным ключом и локальным ответом, без сети: правильный адрес GET, сводка движков, отсутствие ключа в сохранённом отчёте и сообщении об ошибке, отказ при отсутствии ключа.

Полные локальные свидетельства: `%LOCALAPPDATA%\KodVsego\DeveloperAudit\2.23.2-test.1` — отчёты API, список входных файлов, сравнение EXE, результаты проверки подписей и журнал проверки установки. Ключа API в этих файлах нет.
