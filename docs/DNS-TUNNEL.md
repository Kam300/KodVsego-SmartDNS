# DNS-туннель Windows · beta

Для режима без виртуального адаптера см. [Локальный DNS · совместимость](LOCAL-DNS.md).

На главном экране нажмите **«Способ подключения» → «3 · Gemini / NotebookLM · beta»**, выберите провайдера, затем нажмите большую кнопку. Шифрование можно изменить в поле **«Шифрование»** рядом со способом подключения. Отдельное окно управления не открывается; Windows при необходимости запросит права администратора для обработчика. Это быстрый профиль **системного DNS всего ПК**, а не раздельная маршрутизация приложений или доменов. Профиль предназначен для Gemini app и NotebookLM; доступ ChatGPT/Codex им не подтверждается. Провайдеры без заявленной поддержки Gemini и «Авто» не предлагаются в этом профиле. MagicDNS по умолчанию выбирает HTTPS, остальные — опубликованный TLS. Профиль, провайдер и протокол запоминаются; запуск программы сам по себе DNS не включает.

Включение и выключение выполняются большой кнопкой. Пока туннель работает, смена профиля, DNS и протокола заблокирована. Чтобы сменить обычный активный DNS на этот профиль, сначала выключите обычный DNS. Закрытие главного окна ждёт остановки туннеля и восстановления DNS. При наличии незавершённой копии прежнего туннеля обработчик сначала восстанавливает только его адаптеры и лишь затем проверяет новое подключение. Копии других адаптеров сохраняются. Автоматическая перенастройка при смене сети не добавлялась.

Кнопка «Проверить» в карточке DNS выполняет анонимные проверки Gemini и NotebookLM без дополнительных окон; результаты записываются в общий журнал. Вход и генерация не проверяются. В **Настройках → Скачать журнал всей программы (.txt)** сохраняются контекст, снимок текущих DNS и подробные события текущего запуска: обычные операции DNS, проверки, ошибки, туннель и восстановление. Подробности операций с правами администратора передаются обратно в главное окно. Журнал хранится в памяти до закрытия программы, не отправляется автоматически и ограничен 2 МиБ UTF-8 / 4096 записей; потеря старых записей отмечается явно. Короткий отчёт для поддержки по-прежнему содержит лишь последние 24 записи. Секреты, токены и cookie-заголовки удаляются; история посещений не собирается. Старое отдельное окно оставлено только для совместимости диагностического параметра запуска и больше не предлагается в настройках.

В 2.23.6-test.12 добавлен подробный журнал: время с миллисекундами, версия, ОС, этапы запуска/восстановления, исходные DNS текущего адаптера, адрес сервера, протокол, тип вопроса, длительность, RCODE и причины транспортных ошибок. `REFUSED(5)` и `SERVFAIL(2)` учитываются отдельно от транспортных ошибок; NXDOMAIN остаётся обычным отрицательным ответом. Сводные счётчики UDP/TCP, IPv4/IPv6 и отказов очереди записываются каждые 10 секунд и при остановке. Подробности ограничены 500 запросами за сеанс, журнал в окне — примерно 120 тысячами символов; удаление старых записей отмечается явно. Копирование и сохранение TXT выполняются вручную.

Ссылка «Проверить Gemini / ChatGPT / Codex» доступна после подключения и выполняет только анонимные проверки фиксированных адресов. Запросы A/AAAA идут к выбранному шифрованному DNS; HTTPS и WebSocket подключаются к полученным публичным IPv4 с исходным именем и проверкой сертификата. Проверяется также `chatgpt.com/backend-api/codex/responses` с WebSocket Upgrade; статус 101 принимается только с корректным Sec-WebSocket-Accept. Записываются статус, длительность, адрес, Server, Content-Type, cf-ray, cf-mitigated и безопасные поля ошибки JSON либо заголовок HTML. Проверка не читает аккаунты, токены, Gemini API-ключ или куки, не следует перенаправлениям и не отправляет запросы генерации. Ответ 401 означает только требование авторизации, а не успешную работу Codex. Причина обычного HTML 403 без явных признаков остаётся неустановленной. IPv6 HTTPS этой проверкой не проверяется; системная маршрутизация и другой VPN могут влиять на соединение. Остановка отменяет проверку; общий срок — 90 секунд, отдельный уже выполняющийся DNS-запрос ограничен тайм-аутами транспорта.

Имена в журнале проходящих запросов выводятся только для фиксированного набора диагностических доменов ИИ и example.com; прочие заменяются на `<other>`. Тела страниц, куки и история посещений не копируются. Ключи и токены в сообщениях удаляются. Журнал может содержать IP DNS-серверов и GUID адаптеров, необходимые для разбора восстановления.

Windows может показывать «Без доступа к Интернету» именно у виртуального DNS-адаптера: он не имеет маршрута по умолчанию и не переносит веб-трафик. Статус физического Wi-Fi/Ethernet проверяется отдельно. NCSI не отключается, фиктивный успех проверки Windows не подменяется, маршрут по умолчанию в туннель не добавляется. Туннель переносит DNS; доступность конкретного сервиса зависит также от ответа DNS-провайдера, его прокси, HTTPS/WebSocket и аккаунта. [Проверки NCSI у Microsoft](https://learn.microsoft.com/en-us/windows-server/networking/ncsi/ncsi-frequently-asked-questions).

В 2.23.6-test.11 сохранённые копии других адаптеров больше не блокируют текущий Wi-Fi/Ethernet. Проверка конфликта относится только к активным адаптерам выбранного сеанса. Их GUID сохраняются перед применением DNS; выключение, откат и аварийное восстановление работают только с этим списком. Прежние копии других адаптеров сохраняются при каждой записи и не восстанавливаются туннелем, даже если адаптер снова появился. Наличие копии на текущем активном адаптере по-прежнему требует сначала завершить обычное отключение DNS. При полной деинсталляции прежние требования к восстановлению всех копий остаются в силе.

В 2.23.6-test.10 исправлено преждевременное закрытие SafeHandle при установлении канала управления. Повторные подключения, обмен сообщениями, закрытие и тайм-аут проверяются настоящими локальными каналами Windows без загрузки драйвера или изменения DNS. Окно масштабирует шрифты и элементы совместно и ограничивает размер доступной областью экрана.

Эксперимент в 2.23.6-test.9: Настройки → «DNS-туннель · beta». Отдельное окно запрашивает права администратора. Само открытие окна не включает туннель. Перед запуском выключите обычный Smart DNS и другие VPN. Выберите провайдера и DoT/TLS либо DoH/HTTPS, затем «Включить». Для проверки домашнего Wi-Fi начните с DoT/TLS: при недоступном HTTPS приложение не переходит на обычный DNS.

Приложение создаёт временный адаптер Wintun, обрабатывает DNS UDP и TCP по IPv4/IPv6 и отправляет запросы выбранному серверу через собственный шифрованный транспорт. Системные DoH/DoT Windows не используются. Внешний IP не меняется, маршрута по умолчанию в туннель нет, веб-трафик и аккаунты не перехватываются. Браузер со своим DoH может обходить системный DNS. Сервер может оставаться недоступным либо не предоставлять нужную разблокировку.

До изменений проверяются сервер, занятость адресов, политики NRPT, другие VPN и наличие прежней незавершённой резервной копии. После создания интерфейса проверяются настоящие DNS-запросы через локальные UDP и TCP для IPv4 и IPv6; только затем меняются DNS Windows, после чего выполняется повторная проверка. В туннель назначаются DNS-адреса `198.18.254.2` и `fd6b:7653:646e::2`; адреса интерфейса находятся в тех же выделенных префиксах. Меняются только DNS активных Wi-Fi/Ethernet с шлюзом; IP, шлюз, привязка IPv6 и настройки роутера не меняются. Исходные DNS сохраняются обычным механизмом Smart DNS до первой записи, включая параметры системного шифрования.

Обработчик работает в отдельном процессе с закрытым каналом управления. PID обеих сторон и путь программы проверяются. Разрыв канала при закрытии/сбое окна останавливает обработчик и запускает восстановление. Если обработчик аварийно завершается, окно пытается восстановить сохранённые DNS. При незавершённом восстановлении копия остаётся; кнопка «Восстановить DNS» доступна при следующем запуске. Отдельные недоступные адаптеры требуют подключения и повторного восстановления. При выключении сначала восстанавливаются DNS, затем закрывается адаптер.

При изменении набора подключений или их адресов сеанс останавливается. Автоматической настройки новой сети и повторных запросов UAC при смене Wi-Fi нет. Для новой сети туннель включается вручную. Процесс удерживает общий замок операций DNS на время сеанса; обычное окно настроек заблокировано до закрытия тестового окна.

Используется неизменённый [Wintun 0.14.1](https://www.wintun.net/), подписанный WireGuard LLC (`res/wintun/wintun-x64.dll`, SHA-256 `e5da8447dc2c320edc0fc52fa01885c103de8c118481f683643cacc3220dafce`). В установщике MSI и портативном архиве ZIP файл `wintun.dll` идёт в комплекте рядом с `.exe`; в одиночный файл `.exe` библиотека не встраивается, чтобы избежать ложных срабатываний антивирусов. Для запуска способа 3 из одиночного `.exe` положите официальный `wintun.dll` (x64) в одну папку с `.exe` либо используйте MSI / ZIP. Хеш DLL проверяется по SHA-256 перед копированием в `Program Files\KodVsego-SmartDNS-Wintun` и загрузкой. После завершения сеанса временная рабочая копия из `Program Files` удаляется, а файл `wintun.dll` рядом с программой сохраняется. Лицензия готовых DLL: `res/wintun/LICENSE.txt`, также встроена в EXE. Она отличается от MIT исходного кода Smart DNS. Драйвер может оставаться установленным в Windows после закрытия временного адаптера; общие драйверы других программ не удаляются.

Автоматические тесты проверяют DNS-вопросы разных типов, отрицательные ответы, IPv4/IPv6, контрольные суммы, DNS TCP, частичные записи настроек и восстановление. Они не загружают драйвер и не меняют сеть разработчика. Настоящее подключение, остановку и аварийное восстановление нужно проверить на тестовом ПК/виртуальной машине; до этого режим остаётся beta.
