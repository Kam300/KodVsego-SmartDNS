# Автоматическая проверка фактического DNS Windows

В **2.23.6-test.32** для Comss.one, DNS-AI, Zapret DNS, WLrus DNS и Webshift сначала используется официальный чекер провайдера. Для Malw DNS и Malw CF выполняется общая проба специального тестового адреса; в текущем интерфейсе она подписана «Malw отвечает» и не различает обычный Malw и его вариант через Cloudflare. Для остальных провайдеров сохранён механизм MangoProxy, описанный ниже.

Результат доступен после включения на главном экране и вручную: **«Тест DNS → Применение DNS · проверка провайдера»**. Настройка **«Автопроверка применения DNS»** управляет фоновым запуском. Это продолжение существующей настройки, её сохранённый выбор не сбрасывается.

Чекеры вызываются через системное разрешение имени Windows с обычной проверкой TLS-сертификата исходного сайта. Не выполняется прямое разрешение проверяемого имени через принудительно выбранный DNS. Для каждого HTTPS-запроса создаётся новое соединение с адресом, полученным от Windows: кэш соединений .NET не должен продолжать использовать старый адрес после смены DNS. Прокси, cookies, вход и ключи не используются; редиректы не выполняются, тела ответов ограничены 32 КиБ. Содержимое ответа, клиентский IP, уникальные имена и идентификаторы не записываются в журнал.

| Провайдер | Механизм | Результат |
| --- | --- | --- |
| Comss.one | https://check.comss.one/ через системный DNS; требуется HTTP 200 и точная строка Comss.one DNS enabled после удаления краевых пробелов, как в скрипте официальной страницы comss.ru/page.php?id=7315. | Подтверждение только по точному маркеру. Сбой сети, HTTP или другой ответ остаётся неопределённым; подмены успешным сравнением MangoProxy нет. |
| DNS-AI | Контроль `dns-ai.ru/dnscheck`, затем специальный `check.dns-ai.ru/dnscheck`. Принимается HTTP 200/204; отказ любого шага остаётся неопределённым. | «Чекер подтвердил» либо «Не удалось проверить». |
| Zapret DNS | Свежее системное имя `<случайный-id>.check.dns.zapret.moe`, затем до четырёх опросов официального `/api/dns-check`; проверяется boolean `seen`. | Подтверждение либо явное отсутствие подтверждения. Протокол показывается только как сведения чекера. |
| WLrus DNS | Официальный `probe.dns.wlrus.cfd/whoami`; принимаются только точные значения `ours` и `public`. | Подтверждение либо явное отсутствие подтверждения. |
| Webshift | `dns.webshiftvpn.ru/api/dns-check`; проверяется boolean `connected`, строки и числа не принимаются. | Подтверждение либо явное отсутствие подтверждения. |
| Malw DNS / Malw CF | Специальный адрес `test.dns.malw.link`; требуется HTTP 200/204. | Только «Malw отвечает»; по этому ответу нельзя различить обычный DNS и вариант через Cloudflare. |

Ошибка сети, TLS, тайм-аут, неожиданный HTTP-код, неверный JSON и отсутствующий обязательный маркер дают **«Не удалось проверить»**. Смена сети во время проверки аннулирует даже положительный ответ. Отказ официального чекера не запускает MangoProxy автоматически и не заменяется успехом другой диагностики. Нет автоматического переключения провайдера, переприменения DNS или восстановления настроек из-за результата чекера.

Результат относится к пути текущего приложения. Чекер с фиксированным именем может зависеть от DNS-кэша; случайное имя используется там, где его поддерживает официальный механизм. Успех не доказывает работу всех доменов, шифрование всех запросов Windows, маршрут собственного DoH браузера, отдельных правил Antigravity или ответ модели.

## Универсальная диагностика для остальных провайдеров

Начиная с 2.23.6-test.16 после успешного включения обычного DNS, HTTPS/TLS, «Авто» или быстрого профиля Gemini / NotebookLM приложение в фоне проверяет фактические рекурсивные DNS-узлы. Дополнительное окно не открывается. Короткий результат появляется в DNS-карточке главного экрана.

В «Тест DNS» есть вариант «Применение DNS · проверка провайдера»: можно повторить проверку, раскрыть подробности и скопировать результат. Результат автоматического запуска открывается там же. Полные детали включаются в скачиваемый журнал текущего запуска из настроек. Галочка «Автопроверка применения DNS» отключает фоновые проверки; ручная остаётся доступной.

## Как работает

Используется анонимный механизм [MangoProxy](https://mangoproxy.ru/tools/dns-leak-test/), который его страница вызывает через WordPress admin-ajax: `dns_leak_visitor`, `dns_leak_start`, `dns_leak_check`. API страницы не имеет опубликованного стабильного контракта. При изменении формата, блокировке или недоступности сервиса отображается «проверка не завершена», а настройки DNS остаются прежними. Скрипты сайта не исполняются внутри приложения.

Для системного и контрольного путей создаются **разные** тестовые сессии. В каждой разрешаются шесть уникальных имён `N.<anonymous-id>.bash.ws`. Системная выборка использует Windows resolver, контрольная — непосредственно выбранный DNS/HTTPS/TLS из каталога приложения. Затем MangoProxy возвращает публичные IP и названия сетей рекурсивных узлов, которые обратились к авторитетному серверу bash.ws. Контрольные запросы не загрязняют системную выборку. Уникальные имена исключают влияние старых записей этих имён; никакой кэш не очищается.

Проверка имеет общий предел 35 секунд, не блокирует интерфейс, выполняет не более двух DNS-запросов одновременно и повторно читает результат каждой сессии только один раз при пустом ответе. При выключении DNS, новом применении или закрытии приложения запросы отменяются. Уже начатый системный DNS-вызов может завершиться позднее, но его результат не применяется к интерфейсу. Изменение подключения/адресов DNS во время теста делает результат недействительным. Проверка **не** применяет DNS к новым адаптерам и не меняет маршруты.

## Как понимать результат

- «Провайдер не подтверждён»: общая проверка не устанавливает принадлежность DNS. В подробностях видны совпавшие или различные узлы. Пересечение системной и контрольной выборок не подтверждает отсутствие перехвата — обычные запросы могут быть перенаправлены на обоих путях.
- Если узлы различаются, пересечения в двух небольших выборках нет. Возможны VPN, иной DNS, пересылка или разные узлы пула. Это повод проверить детали, а не доказанная утечка.
- «Проверка не завершена»: нет одной из выборок, тайм-аут или ошибка сервиса. Это не оценка работоспособности самого DNS.

Входной IP DNS и исходящий адрес рекурсивного узла могут различаться. Не сравниваем их на буквальное равенство, не классифицируем утечку по стране и не используем рекламный verdict сервиса. Проверка тестового домена не доказывает правильность обработки ChatGPT/Gemini или работу модели. Собственный DoH Chrome/другого браузера здесь не проверяется. OBFUSGATED использует внутренний Next server action с идентификатором сборки, поэтому его непубличный протокол в приложение не встраивается.

## Передаваемые данные

MangoProxy и bash.ws видят служебные тестовые запросы, адрес подключения и адреса рекурсивных узлов. История браузера, содержимое запросов к ИИ, API-ключи, cookies, учётные данные и журнал программы не передаются. HTTPS-запросы идут только на фиксированный endpoint MangoProxy, без редиректов, системных proxy credentials и отключения проверки сертификатов. Идентификаторы тестов и nonce не записываются в журнал. Полученные от сервера адреса и размеры ответов проверяются. Автопроверка включена по умолчанию в этой тестовой версии и отключается в настройках.

## Представление результата в test.32

Общее наблюдение MangoProxy и «Только DNS» показывают информационный значок, без зелёной галочки. Совпадение узлов даже в зашифрованном контрольном пути не заменяет официальный маркер. Зелёный результат применения DNS доступен только при явном подтверждении официального чекера. Проба Malw и недоступность чекера отображаются нейтрально; явный отрицательный ответ чекера — предупреждением. «DNS включён» на главной означает применённую настройку, а подтверждение внешним чекером показывается отдельной строкой.

В технических деталях прямого UDP-теста теперь сохраняются запрошенный адрес DNS, источник пакета и IPv4-ответы. Источник UDP-пакета и одинаковые задержки не аутентифицируют DNS и не исключают перенаправление.

## Строка чекера на главной (test.34)

Сразу под статусом подключения и его пояснением отображается отдельная строка «Чекер сайта». Имя выбранного провайдера и зелёное подтверждение показываются только по положительному результату его официального чекера для текущего провайдера, протокола и способа подключения. Явный отрицательный ответ выделяется предупреждением; ожидание, отключённая автопроверка, недоступность чекера и общая проба Malw остаются нейтральными. При наведении видны источник и время проверки, а также ограничение системным путём Windows: собственный DoH браузера и ответы ИИ не проверяются.

После смены/отключения DNS прежнее подтверждение не показывается. Ручная проверка применения активного провайдера в «Тест DNS» тоже обновляет строку, в том числе при выключенной автопроверке; тест другого провайдера или протокола её не меняет. После неудачной попытки переключения локального DNS автоматическая проверка повторяется для сохранённого прежнего подключения.

## Понятное пояснение Malw (test.36)

На главной строка «Чекер сайта: Malw отвечает» означает, что доступен общий проверочный адрес. Это нейтральный результат. Подсказка и подробный отчёт объясняют, что у Malw DNS и Malw CF через Cloudflare один чекер и он не различает эти варианты. Поэтому использование именно Cloudflare им не подтверждается. Термины «проба» и «профиль не проверен» из короткого статуса убраны. Подсказка разбита на короткие строки.
