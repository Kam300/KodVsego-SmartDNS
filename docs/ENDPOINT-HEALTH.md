# Учёт конечных IP в Авто · Windows

В версии 2.23.10-test.7 отдельно учитываются адреса сервисов, полученные от DNS,
и адреса самих DoH/DoT-серверов. Подбор DNS-провайдеров остаётся параллельным,
до четырёх проверок одновременно; адреса каждого сайта/API проверяются последовательно.

Для каждого ответа рассматриваются до 16 различных публичных IPv4 и до восьми
доступных кандидатов. Ранее проверялось только три адреса. Недавно отвечавший
HTTPS-адрес имеет приоритет в течение двух минут. Отсутствующий в свежем ответе
провайдера IP из памяти не добавляется. Адреса разных провайдеров не смешиваются:
результат и последующее применение сохраняют своего DNS-провайдера.

Транспортный отказ откладывает пару домен/IP на 30 секунд. Подтверждённая
классификатором ошибка региона API откладывает её на пять минут. После ответа
с ошибкой региона проверяется следующий адрес того же провайдера; раньше
первый HTTP-ответ останавливал перебор. Обычный HTTP 400, 429, ошибки входа и
серверные HTTP-ответы не создают региональную блокировку адреса.

Смена сетевого контекста снимает транспортные
штрафы и приоритет HTTPS, но не обнуляет ещё действующее региональное исключение.
Ответы от старого поколения проверки не меняют новое состояние. Обычная успешная
HTTPS-проба не отменяет региональное исключение; точный клиентский ответ с известным
IP может его снять. Память ограничена 512 записями, давно не встречавшиеся записи
удаляются. Состояние хранится в процессе приложения.

Одна проверка провайдера в Авто имеет отменяемый бюджет 45 секунд; закрытие окна
отменяет весь подбор. Уже выполняющиеся DNS-транспорты имеют собственные ограничения
времени и проверяют отмену после завершения своей операции. Таймаут одного провайдера
не отменяет результаты остальных.

В диагностике доступны порядок IP, пропущенные адреса, ошибки и фактически
проверенные конечные IP. Все HTTPS-соединения используют исходное имя SNI и
обычную проверку сертификата. Содержимое анонимных API-ответов не добавляется в
диагностику. Успех HTTPS по-прежнему не является подтверждением генерации модели.

## Antigravity

Явная ошибка региона клиента имеет отдельную пятиминутную паузу маршрута;
тридцатисекундный отказ предварительной проверки её не сокращает. Смена сигнала
сети также не обнуляет эту паузу. Ошибки перегрузки, лимитов и входа не запускают
переключение, как и раньше.

Если журнал клиента содержит публичный удалённый IPv4 сокета на порту 443, он
может быть использован как точное свидетельство отказа. Локальные прокси и ошибки
без IP не позволяют угадать адрес по предыдущей DNS-пробе. Региональные и
транспортные события по-прежнему требуют повторений перед запуском автосмены.

Приоритет после начала ответа модели привязан к комбинации основного DNS и его
протокола, отдельного DNS и его протокола. Другая комбинация не наследует это
подтверждение. Завершение генерации не проверяется.

## Границы

Это улучшение проверки и выбора провайдера в Авто, а не HTTPS-прокси.
Результат проверки не переписывает DNS-ответы, не закрепляет выбранный конечный IP
в клиенте и не переносит уже открытые соединения Antigravity. Клиент может
использовать собственный DNS-кеш или выбрать другой адрес из ответа. Перебор
конечных соединений на уровне клиента, как в прокси-архитектуре Antigravity Unlocker,
эта версия не реализует.
