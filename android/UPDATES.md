# Обновление Android из GitHub

Функция доступна с APK **1.5.0**. Для первого перехода со старых версий скачайте и установите этот APK вручную. Далее приложение сможет находить новые APK самостоятельно.

## Для пользователя

При открытии или возвращении в приложение выполняется запрос к GitHub Releases, если доступна сеть. Автоматические проверки ограничены одним разом в час, включая неудачные запросы. Закрытое приложение не опрашивает GitHub и не получает push-уведомлений.

Если найдена более новая Android-версия, появляется окно «Доступно обновление» с кнопками «Обновить» и «Позже». Последняя откладывает напоминание об этой версии на 24 часа. Другая, более новая версия не скрывается этой отсрочкой. Кнопка «Проверить обновления» позволяет проверить вручную и снова открыть отложенное предложение.

После согласия APK загружается в приватный кэш приложения. На кнопке отображается процент загрузки; нажатием можно отменить загрузку. Пересоздание экрана не прерывает работу. При уничтожении процесса системой незавершённую загрузку нужно повторить. Уже проверенный APK сохраняется до установки или удаления системой кэша.

Приложение проверяет размер и SHA-256, имя пакета, версию, минимальную версию Android и подпись. APK должен быть обновлением именно установленного Smart DNS и иметь тот же набор подписантов. Перед передачей системному установщику проверка выполняется повторно. Установщику предоставляется временный доступ на чтение одного проверенного APK; произвольные файлы не открываются.

Android может попросить разрешить установку из Smart DNS. Это отдельное системное разрешение для источника установки. После возврата из настроек приложение повторно проверяет APK и открывает системное подтверждение установки. Установка без согласия пользователя не выполняется. Системные и корпоративные ограничения установки приложение не обходит.

Проверка получает только публичные сведения GitHub Releases. История DNS-запросов и диагностические отчёты в эти запросы не включаются. При недоступности GitHub автоматическая проверка не мешает работе DNS; ошибку можно увидеть при ручной проверке.

## Для публикации следующей версии

1. Увеличьте `versionName` и `versionCode` в `app/build.gradle`. Например, после 1.5.0 / 7 используйте 1.5.1 / 8.
2. Соберите release APK с **тем же ключом подписи**, что и установленные версии. Сохраните ключ и пароли вне Git.
3. Назовите файл точно: `KodVsego-SmartDNS-Android-1.5.1.apk` — номер должен совпадать с `versionName` внутри APK.
4. Создайте опубликованный GitHub Release в `Kam300/KodVsego-SmartDNS` и прикрепите APK. Рекомендуемый тег — `android-v1.5.1`. Черновики и незавершённые загрузки файлов не учитываются.
5. GitHub обычно предоставляет SHA-256 в поле `digest` файла. Если поле отсутствует, прикрепите `SHA256SUMS.txt` со строкой `SHA256  точное-имя.apk`. Без контрольной суммы APK не предлагается как обновление.

Проверяются последние 60 релизов, выбирается наибольшая версия **из имени Android APK**, а не из номера Windows-релиза или даты публикации. Android APK можно разместить и в общем релизе с EXE. Предварительные релизы учитываются: опубликованные Android-сборки этого проекта имеют такой статус. EXE, установщики Windows и произвольные APK с другим именем игнорируются.

Загрузка разрешена только из этого репозитория GitHub и с его стандартных серверов файлов. Подмена ссылки другим сайтом, APK с другой подписью, меньшим `versionCode` или неподходящей версией Android отклоняется. Новая версия обнаруживается при очередной проверке, а не мгновенно в момент публикации.

## Проверки

Автоматические тесты покрывают выбор Android-релиза, числовое сравнение версий, черновики, повторяющиеся файлы, источники загрузки, контрольные суммы, отмену, размер, подпись, имя пакета и совместимость Android. UI-тесты проверяют окно обновления, отсрочку и ручное открытие. Отдельно проверен доступ ContentProvider только к одному файлу и только на чтение.

Реальный системный установщик и экраны разрешений на физических телефонах при разработке не запускались. Эти проверки не заменяют установку обновления на устройстве.
