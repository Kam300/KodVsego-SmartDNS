# Smart DNS для Android

Нативное приложение на Java для Android 8.0+ (API 26), compile/target SDK 35. [Версия 1.5.1 опубликована](https://github.com/Kam300/KodVsego-SmartDNS/releases/tag/android-v1.5.1) с прежней подписью проекта, versionCode 8. Статус Android остаётся предварительным, без подтверждённого прогона на устройстве. [Инструкция выпуска 1.5.1](RELEASE_1.5.1.md). Не требует root. Исходники Windows находятся в `src/windows/`.

В 1.5.1 обновлён резервный адрес DNS-AI до `45.151.102.219`, каталог провайдеров и домены тестирования берутся из общего [providers.json](../config/providers.json). Если разработчик отключает провайдера в каталоге, новая сборка скрывает его в списке и выбирает доступный DNS вместо сохранённого недоступного варианта. Настройки и виджеты сохраняют прежние номера провайдеров. Это изменение применяется при сборке APK, а не загружается с сервера во время работы приложения.

Кнопка темы использует векторные солнце и полумесяц со звездой вместо символов шрифта. Размер области нажатия — 48 dp, есть ripple и короткое сжатие; доступная подпись описывает тему, которая будет включена.

## Подготовлено к 1.5.2

- Заметная карточка **«Карта сервисов»** рядом с состоянием DNS: сравнение доступных провайдеров по Gemini, ChatGPT, Claude, ElevenLabs и Spotify. Есть выбор сервиса/протокола, остановка, время результата и подробности по нажатию. Запрос входа, капча, ошибка сети и неподтверждённый ответ имеют разные статусы. [Описание карты](../docs/SERVICE-MAP.md).

- DoH / HTTPS и DoT / TLS с проверкой сертификата и без понижения до открытого DNS.
- Смена провайдера и протокола при включённом DNS, после проверки замены и без пересоздания VPN.
- Настройки видимости провайдеров, ссылки на информацию о DNS и измерение задержки.
- Ручной Авто-подбор по DNS-ответу и задержке. Включаемая автосмена при трёх ошибках DNS ограничена одной попыткой в минуту и тремя за десять минут. Собственные успехи DNS отменяют ещё не применённый результат. Отключённая опция и скрытый провайдер повторно проверяются перед применением.
- Копирование результатов и сохранение общего журнала через системный выбор файла. Журнал начинается при открытии экрана/создании службы, хранится в приватных файлах (два файла примерно по 256 КиБ), переживает перезапуск процесса и не отправляется автоматически. История пользовательских DNS-имён и журналы других приложений не собираются; ключи и параметры URL скрываются.

Авто проверяет DNS-ответ на `example.com`, а не работу сайта, вход в аккаунт или генерацию ИИ. Системные ограничения VPN и частного DNS сохраняются. Функций Antigravity нет.

Тестовый вариант `1.5.2-test.12` имеет отдельный package `ru.kodvsego.smartdns.test` и подпись debug: устанавливается отдельно и не заменяет опубликованное приложение. Релизный APK 1.5.2 / 9 должен подписать владелец прежнего ключа. [Инструкция передачи разработчику](RELEASE_1.5.2.md).

На главном экране — подключение, провайдер, DoH/DoT, Авто, тема, тест и строка чекера. В шестерёнке — видимость провайдеров, автосмена при ошибках, журнал, виджеты, обновления и системные сетевые настройки.

## Логика

Интерфейс 1.4 использует голубые акценты #02A5CF, фиолетовое свечение и шрифты Manrope/Unbounded, встроенные вместе с OFL-лицензиями. `PowerButton` рисует кнопку без выделения bitmap/layout-объектов на каждом кадре. Короткие переходы выполняются `ValueAnimator`/`ViewPropertyAnimator` с учётом `areAnimatorsEnabled()`. Постоянный индикатор нужен только при подключении и останавливается при скрытии/удалении окна. В подключённом состоянии пульсации нет. Иконки кэшируются, карточки не пересобираются при неизменном провайдере, фоновый опрос UI остановлен вне активного экрана.

1. `MainActivity` сохраняет выбранного провайдера, протокол DNS, тему, видимость провайдеров и настройку автосмены в приватных SharedPreferences. Запуск проверяет физическую сеть и строгий частный DNS. При наличии другого VPN показывается подтверждение его замены.
2. `VpnService.prepare()` запрашивает системное согласие. При отмене служба не запускается. На Android 13+ отдельно запрашивается разрешение уведомлений; отказ не подменяет согласие на VPN.
3. `DnsVpnService` запускает foreground-уведомление. Перед созданием TUN выполняется контрольный DNS-запрос `example.com`. Доступный адрес в ответе является проверкой DNS, а не доступности сервисов.
4. Создаётся локальный интерфейс `10.111.0.1/32`, DNS `10.111.0.2`, единственный маршрут `10.111.0.2/32`, MTU 1500. IPv6 разрешён вне туннеля через `allowFamily(AF_INET6)`. Маршруты `0.0.0.0/0` и `::/0` не добавляются.
5. `IpPacket` разбирает IPv4 UDP/TCP к порту 53, отклоняет фрагменты, неверные длины и чужие адреса. `DnsWire` проверяет формат вопроса, transaction ID, домен, тип и класс ответа. NXDOMAIN/NODATA передаются системе без подмены на успех.
6. Обычный DNS отправляется на основной сервер через сокет, привязанный к физической сети. При сетевой ошибке или SERVFAIL/REFUSED используется резервный. UDP с TC повторяется через TCP. Входящие UDP-ответы больше 512 байт возвращаются как усечённые с TC: клиент может повторить запрос по TCP.
7. `TcpDnsProxy` реализует отдельный ограниченный TCP endpoint для DNS: SYN/ACK, последовательности с переполнением 32 бит, сборку DNS-фрейма из сегментов, упорядоченные ответы, подтверждения, повторную передачу, окно, FIN/RST и таймаут простоя. Не является универсальным сетевым TCP-стеком. Одновременно допускается до 64 соединений, 8 ожидающих ответов на соединение; размер DNS-фрейма — до 65535 байт. Фрагменты IP не собираются.
8. DoH идёт через OkHttp с системной проверкой TLS/имени узла, HTTPS POST `application/dns-message` и согласованием HTTP/2. Это требуется в том числе DNS-AI. Прокси отключён, перенаправления запрещены, ответ ограничен 65535 байтами. При ошибке HTTPS возврата к UDP нет. DoH endpoint соединяется по IP из общего каталога с исходным именем узла и проверкой сертификата; сами пересылаемые DNS-запросы идут внутри HTTPS. DoT использует TLS на порту 853, IP и имя сертификата из того же каталога. Перехода на обычный DNS при ошибках DoH/DoT нет.
9. Сокеты UDP/TCP защищены `VpnService.protect()` и привязаны к физической сети. HTTPS использует SocketFactory/DNS физической сети. При смене сети HTTPS-клиент обновляется. При отсутствии сети запросы получают SERVFAIL; служба остаётся доступна для отключения и повторных запросов после возвращения сети.
10. Остановка из приложения, уведомления, виджета или отзыв разрешения немедленно сбрасывает состояние и отменяет поколение подключения (`SessionOwner`). Поздний результат отменённого подключения уничтожается. Закрытие TUN, сокетов, HTTP-вызовов и TCP-состояния выполняется в отдельных потоках очистки; UI не ожидает сетевых блокировок. Сначала закрывается файловый дескриптор TUN, затем очереди и соединения. Android возвращает сетевые DNS автоматически; собственных изменений настроек ОС для отката нет. Фоновый автозапуск и always-on отключены. После уничтожения службы ОС исходные сетевые DNS снова могут использоваться — это не режим постоянной блокировки утечек.

Очередь обработки ограничена 64 заданиями и четырьмя рабочими потоками. Ошибки переполнения обрабатываются ответом SERVFAIL; длинные запросы и соединения ограничены таймаутами. История доменов на диск не пишется.

При `onPause` останавливаются опрос UI и анимации. При `onResume` сбрасываются нажатие, масштаб, прозрачность и незавершённые переходы; состояние службы перечитывается. Отступы status/navigation bar применяются к ScrollView с отсечением прокручиваемого содержимого.

## Выбор DNS и кнопка запуска

Вместо Spinner открывается нижняя панель с прокручиваемыми карточками провайдеров. На карточке указаны сервисы, протоколы и текущий выбор. Без VPN выбор сохраняется для следующего запуска. При активном VPN новая конфигурация проверяется и применяется без остановки TUN; при ошибке остаётся прежний DNS. Выбор заблокирован только во время подключения или смены. При уничтожении Activity панель закрывается.

На основном экране и в панели скрыты полосы прокрутки, прокрутка жестом сохранена. Между блоками — 20 dp, между вторичными кнопками — 12 dp. Блок «Как работает на телефоне» удалён; добавление виджета и сетевые настройки доступны отдельно. Нажатие на кнопку питания запускает короткую волну, ожидание подключения — индикатор. Эффекты учитывают системное отключение анимаций, сбрасываются при уходе в фон и не блокируют повторное нажатие для отмены.

## Виджеты

Доступны компактный 2×1 и расширенный 4×2 виджеты. Добавление — кнопкой «Добавить виджет» или через меню лаунчера. Внешний размер зависит от сетки рабочего стола.

Проверяются поддержка запроса, его результат и исключения лаунчера. Принятый запрос означает только передачу лаунчеру, а не успешное добавление. Если окно не появилось, используйте «Как добавить вручную»: главный экран → удержание пустого места → «Виджеты» (или настройки главного экрана) → «Код Всего · Smart DNS». Инструкция доступна и при заявленной поддержке автоматического добавления.

`DnsWidget`/`CompactDnsWidget` используют RemoteViews и неизменяемые PendingIntent. Выключение направляется прямо в службу, включение открывает MainActivity для проверки сети и согласия VPN. Состояние обновляется при изменении службы и обновлении APK, без периодического опроса. Нажатие на карточку открывает приложение.

Значок питания задан Android VectorDrawable (`ic_power.xml`); общий SVG-исходник — `../res/power.svg`. Настройки дополнительного DNS удалены из Android.

## Проверка провайдера

«Тест DNS» отправляет запросы к основному и резервному серверу отдельно. В режиме DoH проверяется HTTPS endpoint; в DoT — TLS-соединение с сервером. В отчёте указаны домен, транспортная цель, время или ошибка. Тест можно остановить. Тест не включает VPN и не меняет системные настройки; привязка к физической сети позволяет проверять провайдера и при активном локальном туннеле.

Сервисные иконки берутся из `../res/service-icons` во время сборки и включаются в APK. Загрузки иконок в рантайме нет.

## Сборка

Требуются JDK 17, Android SDK Platform 35 и Build Tools 34.0.0. Android Studio подходит, но для командной сборки не обязателен. Gradle Wrapper 8.9 включён; SHA-256 дистрибутива закреплён в конфигурации. AGP — 8.7.3. При первой сборке нужны доступ к Google Maven/Maven Central и установленные лицензии SDK.

Создайте `local.properties` (файл исключён из Git):

```properties
sdk.dir=C:/Users/YOUR_USER/AppData/Local/Android/Sdk
```

Windows:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

Linux/macOS:

```sh
bash gradlew testDebugUnitTest lintDebug assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Это debug-подпись для разработки. Debug и release имеют разные ключи, поэтому смена типа подписи требует удаления ранее установленной сборки.

Для пользовательской проверки без замены установленного приложения есть отдельная сборка:

```powershell
.\gradlew.bat testPreviewUnitTest lintPreview assemblePreview
```

APK: `app/build/outputs/apk/preview/app-preview.apk`. Имя в списке приложений — «Smart DNS — тест», пакет `ru.kodvsego.smartdns.test`, версия `1.5.1-test.1`. Используется debug-подпись; приложение устанавливается рядом с основной версией и хранит настройки отдельно. Перед подключением выключите DNS VPN в другой копии: Android разрешает один активный VPN. Это не APK для выпуска или обновления основной версии.

### Подпись APK

Создайте собственный ключ, например:

```sh
keytool -genkeypair -keystore smartdns.p12 -storetype PKCS12 -alias smartdns -keyalg RSA -keysize 3072 -validity 10000
```

Ключ и пароль сохраняйте вне Git. Скопируйте `signing.properties.example` в `signing.properties` и укажите путь к своему ключу, alias и пароль. Затем:

```powershell
.\gradlew.bat testDebugUnitTest lintRelease assembleRelease
```

Результат: `app/build/outputs/apk/release/app-release.apk`. Если `signing.properties` отсутствует, release APK остаётся неподписанным. Для обновления установленного приложения нужен **тот же ключ** и больший `versionCode`. Потеря ключа означает невозможность обновить прежнюю установку.

Первый опубликованный APK подписан отдельным локальным ключом проекта. На машине первоначальной сборки он находится в `../dist/signing/kodvsego-android.p12`, параметры — в игнорируемом `signing.properties`. Оба файла нужно сохранить в надёжной резервной копии; в GitHub они не отправляются. Это обычная Android-подпись пакета, а не подпись Google Play.

Проверка:

```sh
apksigner verify --verbose --print-certs app/build/outputs/apk/release/app-release.apk
```

## Проверки и границы подтверждения

JUnit проверяет выбор провайдера, запрет понижения DoH, DNS-формат, соответствие ответов, NXDOMAIN, некорректные пакеты, контрольные суммы, DNS TCP, повторную передачу и лимит соединений. Локальный TLS-сервер проверяет HTTP/2, отправку DNS POST, ошибки HTTP, запрет redirect, размер/тип ответа, подмену ID и отказ от недоверенного сертификата. Внешние сервисы в unit-тестах не вызываются.

Robolectric 4.14.1 проверяет Activity и службу на API 28 и 35: возврат из фона, касание после отменённой анимации, кнопку отключения, отмену подключения и остановку из уведомления при блокирующем закрытии ресурса. Отдельно проверяются системные отступы API 35, действия обоих виджетов и размер компактного виджета. `SessionOwnerTest` проверяет поколения и асинхронную очистку. Эти проверки используют имитацию Android, не реальный VPN/TUN.

Android Lint запускается для debug/release. Единственное точечное исключение `ForegroundServicePermission` относится к AGP 8.7: проверка требует alarm permission для `systemExempted`, хотя VPN с согласованием системы является отдельным допустимым случаем. Приложение не просит права будильника. Основание: [Android foreground service types — systemExempted](https://developer.android.com/develop/background-work/services/fgs/service-types#system-exempted).

Для подтверждения на телефоне/эмуляторе ещё нужно проверить:

- установку и запуск на API 26, 33, 34 и 35+, обе темы, маленький экран и поворот;
- отмену/подтверждение согласия VPN и уведомлений;
- фактическую доставку системных A/AAAA запросов в TUN и UDP/TCP-ответов обратно;
- обычный DNS и DoH каждого провайдера, основной/резервный сервер и недоступность endpoint;
- Wi-Fi → мобильная сеть, отсутствие сети, возврат сети и спящий режим;
- строгий частный DNS, собственный DNS браузера и конфликт с другим VPN;
- отключение кнопкой/уведомлением/системой и восстановление сетевого DNS;
- ошибки TLS и отсутствие перехода DoH → обычный DNS;
- оба виджета в лаунчере, перезапуск процесса и обновление APK поверх предыдущей версии.

На этапе создания APK подключённого устройства не было. Сборка, unit-тесты и статический анализ не заменяют эти проверки. Известные ограничения — DNS-only, IPv4 TUN, отсутствие IP-фрагментации, отсутствие always-on/lockdown и невозможность перезапустить чужие приложения.

Документация Android: [VpnService](https://developer.android.com/develop/connectivity/vpn), [VpnService.Builder](https://developer.android.com/reference/android/net/VpnService.Builder).

## Чекеры провайдеров в 1.5.2-test.12

После подключения и смены DNS проверяется текущий системный путь Android через официальные проверки Comss.one, DNS-AI, Zapret DNS, WLrus, Webshift, Malw DNS / CF. Принудительного обращения к выбранному upstream нет. Нажатие строки под статусом открывает подробности, копирование и повторную проверку; результат попадает в журнал. Автопроверку можно отключить в шестерёнке. Запросы отправляются сайтам выбранного провайдера, которые видят обычные сетевые данные соединения.

Malw подтверждает только общую пробу, без различения Cloudflare-профиля. Для остальных провайдеров показано отсутствие подключённого чекера, без выдуманного успеха. HTTP-ошибка, тайм-аут и неправильный формат — «не удалось проверить». Вход, ответы моделей и собственный DoH браузера не проверяются. Смена подключения/конфигурации отменяет старый результат. Android 10+ использует системный DNS API с обходом кэша; на Android 8–9 применяется системный resolver, кэш которого может задержать обновление. Это отражено в подробностях результата.

## Интерфейс и проверка VPN в test.5

DoH / DoT / обычный DNS выбираются сразу на главном экране; недоступный протокол отключён. Между карточками и кнопками добавлены отступы, Авто и тест расположены рядом, длинный отчёт ограничен превью и открывается по нажатию. Ошибка подключения показана коротким заголовком и подсказкой; исходный технический текст доступен в подробностях и журнале.

Авто до запросов и перед применением результата проверяет сторонний VPN, наличие физической сети и частный DNS. Собственный активный туннель Smart DNS исключается из признаков стороннего VPN. Служба подключения также проверяет конфликт перед preflight. EPERM и отказ protect сокета не означают недоступность DNS-сервера: Android может запрещать обход VPN / lockdown. Приложение не отключает чужой VPN и не меняет системную блокировку.

## Каталог DNS без переустановки

В настройках добавлен «Обновлять адреса DNS автоматически»: проверка раз в сутки, ручная проверка и сохранённая рабочая копия. Работающее подключение не меняется. Общий формат, ревью изменений сайтов и публикация описаны в [REMOTE-CATALOG](../docs/REMOTE-CATALOG.md). Удалённая проверка заработает после публикации `config/catalog.json` в основной ветке.
